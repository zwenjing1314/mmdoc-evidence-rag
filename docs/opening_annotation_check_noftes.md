# 开题前 QA 标注人工抽查记录

## 一、抽查目的

本次抽查对象是：

```text
data/raw/cn_annual_reports/qa_annotations_v2.csv
```

抽查目标不是全面修改数据，而是先找出最容易出错的标注类型，为后续人工校验和代码修正提供依据。

本次重点检查 10 条左右高风险样本，覆盖：

1. 数值答案是否抽取正确。
2. 单位是否正确。
3. 负数或括号数字是否保留。
4. 证据页是否能支撑答案。
5. 风险文本类问题是否真正对应“风险”。
6. 同比增减幅度是否误抽了其他百分比。

## 二、总体结论

这批 V2 标注已经比旧版更适合开题前实验，因为它新增了单位、证据文本、问题类型、难度、来源章节等信息。

但自动规则生成仍然存在明显错误，尤其集中在以下几类：

1. **指标关键词过宽**：例如“资产总额”会误命中“纳入评价范围单位资产总额占比 99.15%”。
2. **数值抽取太靠前**：例如归母净利润问题误抽到年份 `2025`。
3. **研发类问题容易误抽序号**：例如把“2、人才储备优势”中的 `2` 当成研发投入。
4. **单位提取不完整**：有些指标写成“营业收入（元）”，不是“单位：元”，当前规则没有识别括号里的单位。
5. **风险类文本过宽**：有些风险问题抽到衍生品交易风险或研发材料风险，不一定是公司年度报告中最核心的风险因素。
6. **同比增减问题容易误抽无关百分比**：例如把“核心技术相关收入占营业收入比例达 99%以上”误当成营业收入同比增减。

因此，`qa_annotations_v2.csv` 可以作为实验初始标注，但开题前建议生成一份人工修正版本：

```text
data/raw/cn_annual_reports/qa_annotations_v2_reviewed.csv
```

## 五、关于字段是否过多的判断

我认为现在字段确实偏多，但不是完全没有必要。

更准确地说：

```text
字段数量多，是因为它同时承担了“实验运行”和“人工校验/论文分析”两个功能。
```

如果只为了跑检索实验，核心字段其实只需要：

```text
query_id
doc_id
question
answer
evidence_pages
question_type
is_answerable
```

如果要做细粒度证据检索，还需要：

```text
value_evidence_text
unit_evidence_text
value_evidence_pages
unit_evidence_pages
```

如果要做可信性实验，还需要：

```text
answer_unit
raw_answer_value
normalized_answer
difficulty
source_section
notes
```

所以我的建议不是删除字段，而是把字段分层理解。

## 4. 可以考虑弱化的字段

这些字段可以保留，但不一定需要在人工标注主表中频繁查看：

```text

```

原因是：

```text

```

如果后续觉得表太宽，可以把部分字段移到 metadata 或单独的辅助表中。
