## 可直接粘贴版本

```text
（一）总体框架设计

本文拟构建一个面向多模态长文档的多粒度证据检索与可信生成框架。整体框架由六个模块组成：文档解析模块、证据节点构建模块、多索引构建模块、页面—区域协同检索模块、证据增强生成模块和可信验证模块。

第一，文档解析模块。该模块以 PDF 长文档为输入，利用 PyMuPDF、Docling 或 PaddleOCR 等工具抽取页面文本、页面图像、文本块、表格块、图表区域、页码、阅读顺序和区域坐标等信息。对于原生 PDF，优先使用 PyMuPDF 抽取页面文本和文本块；对于扫描件或图片型 PDF，则接入 OCR 工具获得文字和位置信息。该模块输出 page-level records 和 layout blocks，为后续证据节点构建提供基础。

第二，证据节点构建模块。该模块将解析得到的页面、段落、表格块、表格行、图表区域等统一表示为 evidence node。每个节点包含 node_id、doc_id、page_id、node_type、bbox、text、reading_order、source 和 metadata 等字段。对于中文年报中的财务表格，系统根据营业收入、归属于上市公司股东的净利润、经营活动产生的现金流量净额、研发投入、资产总额等指标识别表格行级证据节点。该模块输出标准化的 documents、pages、nodes 和 queries 四类数据表。

第三，多索引构建模块。该模块面向不同粒度的证据单元建立索引，包括页面级文本索引、区域级文本索引、节点类型索引和版面元数据索引。页面级索引用于快速召回相关页面，区域级索引用于在候选页面内定位具体证据。后续实验中可进一步加入页面图像向量索引和区域图像向量索引，以支持视觉检索和多模态融合。

第四，页面—区域协同检索模块。该模块采用两阶段检索结构。第一阶段进行页面级粗召回，使用 BM25、TF-IDF/Dense 或 BGE-M3 等方法计算问题与页面之间的相关性，得到 Top-k 候选页面。第二阶段在候选页面内部进行区域级细检索，计算问题与 paragraph、table_block、table_row 等 evidence node 的相关性，并结合页面级得分、节点类型和关键词匹配信号进行重排序。该模块输出按得分排序的证据节点列表。

第五，证据增强生成模块。该模块将检索得到的证据节点组织为 evidence cards，每张 evidence card 包含页码、节点类型、证据文本、区域坐标、检索得分和来源文档。生成阶段要求模型只基于 evidence cards 中的证据回答问题，并输出对应引用信息。对于财务数值类问题，输入中显式保留指标名称、数值、单位和证据页，减少单位错误和无依据生成。

第六，可信验证模块。该模块对生成结果进行证据支持性检查。对于数值型问题，验证答案中的指标名称、数值和单位是否能在证据节点中找到支持；对于文本型问题，验证回答内容是否被检索证据覆盖；对于证据不足或证据冲突的情况，系统执行二次检索或拒答。该模块输出 supported、insufficient 或 conflict 等判断结果。

整体流程可以概括为：

PDF 文档输入 → 文档解析 → 证据节点构建 → 多粒度索引 → 页面级粗召回 → 区域级细定位 → 证据卡片组织 → 证据约束生成 → 支持性验证 → 输出答案与证据来源。
```

## 可直接粘贴版本

```text
（二）关键算法与模块实现

1. 证据节点构建算法。设文档集合为 D，每篇文档 d 由若干页面 p 组成。系统首先对每个页面进行解析，得到页面文本 T_p、页面文本块集合 B_p={b_1,b_2,...,b_n} 及其坐标信息。对于每个文本块 b_i，若其包含多个数字或包含关键财务指标词，则标记为 table_block；否则标记为 paragraph。对于包含“营业收入”“归属于上市公司股东的净利润”“经营活动产生的现金流量净额”“研发投入”“资产总额”等关键词且附近存在数值的文本块，进一步抽取 table_row 级证据节点。最终每个节点 e_i 被表示为 e_i=(node_id, doc_id, page_id, node_type, bbox, text, reading_order, metadata)。

2. 页面级召回算法。给定查询 q 和页面集合 P，系统将每个页面文本表示为向量或稀疏词项表示，计算 q 与每个页面 p 的相关性得分 S_page(q,p)。在 baseline 中，本文采用 BM25 进行关键词匹配；在语义检索中，采用 TF-IDF/Dense fallback 或 BGE-M3 embedding 计算相似度。根据 S_page(q,p) 排序，选取 Top-k 页面作为候选页面集合 P_k。

3. 区域级检索算法。对于候选页面集合 P_k，系统收集其中所有 evidence nodes，形成候选节点集合 E_k。然后计算查询 q 与每个节点 e 的相关性得分 S_region(q,e)。对于财务数值问题，系统在节点得分中加入指标关键词匹配和节点类型先验，使 table_row 和 table_block 类型节点在相关问题中获得更高优先级。

4. 排序融合算法。为了同时利用页面级相关性和区域级相关性，系统将页面级排序和节点级排序进行融合。本文采用 Reciprocal Rank Fusion 或加权融合策略。融合得分可表示为：

S_final(q,e)=αS_region(q,e)+βS_page(q,page(e))+γS_type(q,e)

其中 S_region 表示节点级相似度，S_page 表示节点所在页面的页面级得分，S_type 表示节点类型与问题类型的匹配得分，α、β、γ 为权重参数。最终根据 S_final 对候选证据节点排序。

5. 证据卡片构建算法。系统将 Top-k 证据节点转换为 evidence cards，每张卡片包含 page_id、node_id、node_type、bbox、text、score 和 source 等字段。与普通文本 chunk 不同，evidence card 保留了页码、区域位置和节点类型，因此可以直接用于答案引用和支持性验证。

6. 答案支持性验证算法。对于数值型问题，系统从生成答案中抽取指标名称、数值和单位，并检查这些元素是否出现在证据卡片中；若数值和单位均能被证据支持，则标记为 supported；若只找到相关页面但缺少关键数值或单位，则标记为 insufficient；若答案数值与证据数值不一致，则标记为 conflict。对于文本型问题，则根据证据覆盖度和检索置信度判断回答是否被证据支持。
```
