## 3. 方法说明

| 方法 | 含义 | 作用 |
| --- | --- | --- |
| BM25-page | 关键词页面级检索 | 基础关键词 baseline |
| Dense-page | 语义页面级检索 | 页面召回 baseline |
| Hybrid-page | BM25 与 Dense 页面召回结果用 RRF 融合 | 检验关键词与语义融合是否提升页面召回 |
| Page→Region | 先 Dense 页面召回，再在候选页内检索节点 | 检验两阶段证据定位 |
| Hybrid-Page→Region | 先 Hybrid 页面召回，再在候选页内检索节点 | 检验融合页面召回对区域定位的影响 |
| Global-Region | 不经过页面召回，直接在整篇文档所有节点中检索 | 判断直接区域检索效果 |
| Oracle-Page→Region | 使用 gold evidence pages 作为候选页，再做区域检索 | 判断区域定位能力上限 |

## 4. 当前观察

1. `Dense-page` 的 Page Recall@5 和 Page Recall@10 明显高于 `BM25-page`，说明语义检索比纯关键词检索更适合当前中文年报页面召回。
2. `Hybrid-page` 的 Page Recall@10 达到 0.6562，高于 `Dense-page` 的 0.6188，但 Page Recall@5 低于 `Dense-page`，说明当前 RRF 融合扩大了 Top-10 覆盖，但前排排序还不够好。
3. `Page→Region` 的 Region Hit@5 为 0.2125，说明两阶段方法已经能返回部分正确证据节点，但区域定位能力仍需要提升。
4. `Global-Region` 的 Region Hit@5 为 0.2812，高于当前 `Page→Region`，说明直接节点检索在当前数据上有一定优势，也说明页面候选限制可能会漏掉正确节点。
5. `Oracle-Page→Region` 的 Region Hit@5 达到 0.7875，说明如果正确页面已知，区域级节点检索可以取得较高上限。因此当前瓶颈之一是页面召回和候选页面排序。
6. `Hybrid-Page→Region` 结果较差，说明“页面级融合提升 Top-10 召回”不一定会直接提升区域级证据定位。后续需要分析融合后的页面排序、候选节点噪声和 Page→Region 的融合策略。

## 5. 当前结论

当前实验已经从单一 baseline 扩展为较完整的检索实验矩阵。

可以支撑以下分析：

```text
页面级检索、直接区域检索、预测页面到区域检索、oracle 页面到区域检索之间的差异。
```

目前最重要的实验发现是：

```text
区域检索本身并非完全无效；当 gold pages 已知时，Region Hit@5 可以达到 0.7875。当前普通 Page→Region 与 oracle 上限差距较大，说明后续应重点改进页面召回、页面排序和候选证据集合构建。
```

## 6. 对后续实验的启发

下一步建议优先做：

1. 分析 `Hybrid-page` 的 Top-5 排序为什么低于 `Dense-page`。
2. 调整 Hybrid 融合策略，例如改变 RRF `k` 值、提高 BM25/Dense 候选数量、引入加权融合。
3. 在 `Page→Region` 中尝试不同页面候选数量，例如 `page_top_k=5/10/20/30`。
4. 实现 `single-node vs evidence-set`，从 Top-K 节点中构建最小充分证据集合。
5. 引入证据充分性判断，评价 evidence set 是否覆盖指标、年份、数值和单位。
