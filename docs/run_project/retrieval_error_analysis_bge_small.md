## 2. 关键错误模式

- 总问题数：`160`
- Hybrid-page Top10 页面命中：`90`，占比 `0.5625`
- Hybrid-Page→Region Top5 节点命中：`31`，占比 `0.1938`
- Global-Region Top5 节点命中：`41`，占比 `0.2562`
- Oracle-Page→Region Top5 节点命中：`157`，占比 `0.9812`
- Hybrid-page 已召回 gold page 但 Hybrid-Page→Region 未命中 gold node：`59`
- Oracle 能命中但 Hybrid-Page→Region 不能命中：`126`
- Global-Region 能命中但 Hybrid-Page→Region 不能命中：`21`

解释：

1. `Oracle-Page→Region` 的 Region Hit@5 很高，说明只要正确页面已知，当前节点切分与节点级检索基本可以找到正确证据。
2. `Hybrid-Page→Region` 与 Oracle 差距很大，主要问题不是节点库完全不可用，而是预测页面阶段和候选节点组织阶段损失较大。
3. `Global-Region` 高于 `Hybrid-Page→Region`，说明页面过滤会漏掉一部分原本能被全局节点检索找到的证据。

## 7. 结论与下一步

当前误差分析支持以下结论：

1. `Hybrid-page` 是当前较好的页面召回方案，但 Top10 页面召回仍只有约三分之一到一半，页面阶段仍是主要瓶颈。
2. `Oracle-Page→Region` 的上限很高，说明节点级证据定位并不是不可行，关键在于如何给区域检索提供更好的候选页面或候选节点。
3. `Global-Region` 比 Hybrid-Page→Region 更高，说明“先页面后区域”的过滤策略会损失一部分正确节点。
4. 下一步不建议继续堆更多 baseline，建议先做 `candidate expansion + evidence set`：保留 Hybrid-page 候选页面，同时并入 Global-Region 的高分节点，再从候选节点中选择最小充分证据集合。

建议下一步开发：

```text
Candidate Pool = Hybrid-page TopK pages 内 nodes + Global-Region TopK nodes
然后构建 Evidence Set V1：覆盖指标、年份、数值、单位。
```
