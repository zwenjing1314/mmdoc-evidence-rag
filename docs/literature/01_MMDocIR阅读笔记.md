# MMDocIR: Benchmarking Multimodal Retrieval for Long Documents
## 1.论文解决的具体问题：
这篇论文主要解决了现有长文档多模态基准不完善、缺乏细粒度评估的问题。具体来说，现有的评估基准存在以下缺陷：
- 问题脱离检索本质：很多现有数据集的测试问题直接借用自视觉问答（VQA）任务，默认已经给出了相关图片，而不是真正考察系统在几百页文档中的“大海捞针”能力。
- 缺乏完整的长文档上下文：许多基准只提供单页或碎片化的文档片段，无法反映真实的业务场景。
- 检索粒度太粗糙：以前的基准大多只能评估系统能否找到“哪一页”，而无法精确定位到具体的段落或图表。
## 2.MMDocIR是什么
MMDocIR（Multimodal Document Information Retrieval）是一个大规模、细粒度的多模态长文档检索评估基准和数据集。
- 页级检索：给出一个用户问题，系统需要从整篇长文档中定位出包含证据的最相关页面。
- 版面级检索：这是更细粒度的任务。系统不仅要找到那一页，还要用边界框（Bounding Box）精准框出具体的版面元素——比如到底是哪个段落、哪个数学公式、哪张图片或哪张表格回答了这个问题。
在数据规模上，它包含：
- 高质量评估集：313篇长文档（平均65.1页，涵盖10个不同领域），以及专家手工打磨标注的 1,658 个问答对。
- 大规模训练集：包含 6,878 篇文档和超过 73,000 个带标注的问答对，用于支持模型的训练。
## 3.MMDocIR数据集构建流程
评估集构建（313 个文档 + 1658 个查询）
- 文档筛选：从 MMLongBench-Doc 与 DocBench 两个长文档基准中，筛选 364 个完整长文档（平均页数 65.1），覆盖 10 个核心领域。
- 问题优化：过滤不适配检索场景的问题（如摘要类、统计类、需外部网络搜索的问题），最终保留 1658 个查询。
- 双粒度标注：
  - 1.页面级标注：人工标注包含答案证据的具体页面，修正了 MMLongBench-Doc 中 21.3% 的错误页面标签；
  - 2.布局级标注：利用 MinerU 工具自动检测文档布局（文本段落、表格、图表等），对工具未识别的元素手动标注边界框，最终生成 2638 个布局级标签
- 质量控制：通过 “交叉验证 + 随机抽检” 确保标注一致性，页面级标注 F1 达 95.2，布局级达 87.1。
训练集构建（6878 个文档 + 73843 个查询）
- 文档来源：整合 MP-DocVQA、SlideVQA、TAT-DQA 等 7 个多模态文档数据集，追溯并恢复原始完整文档
- 标签生成：采用半自动化流程，为缺乏标签的数据集生成页面级与布局级标签（仅 4 个数据集支持布局级标签）
- 硬负例采样：通过 ColPali 检索器筛选与正例高度相似的无关页面作为硬负例，增强训练数据的区分度。
## 4.MMDocIR数据集的核心特征
基础统计信息：
- 评估集有文档数量313；平均页数65.1；查询数量是1658；标注类型是页面级（2107）+ 布局级（2638 个）；涵盖领域：研究报告、学术论文、财务报告等 10 个领域
- 训练集有文档数量6878；平均页数32.6；查询数量是73843；标注类型是页面级 + 部分布局级；涵盖领域：医疗、金融、法律、学术等多领域
模态与问题分布
- 模态分布（评估集）：文本占 60.4%，图像占 18.8%，表格占 16.7%，其他（公式、标题）占 4.1%，不同领域模态分布差异显著（如财务报告表格占比 29.2%，政府文档文本占比 88.2%
- 问题证据类型：文本类 44.7%、图像类 21.7%、表格类 37.4%、布局 / 元信息类 11.5%，其中 254 个问题需跨模态推理，313 个需跨页整合证据。
双任务定义
- 页面级检索：给定查询，返回包含答案证据的 Top-k 页面；
- 布局级检索：给定查询，返回页面中包含答案证据的具体元素（文本段落、表格、图表等），通过边界框重叠度判断匹配度。
## 5.检索器类型与实验设置
文本驱动检索器（6 款）
通过将多模态内容转化为文本进行检索，核心差异在于文本转化方式与编码策略：
- 文本转化方式：
  - OCR-text：通过 Tesseract OCR 工具提取文本，仅保留字符信息；
  - VLM-text：通过 GPT-4o、Qwen-VL 等视觉语言模型生成视觉元素（表格、图像）的描述文本，保留语义与结构信息；
- 代表模型：DPR、ColBERT、BGE、E5、Contriever、GTE，其中 ColBERT 为 token 级编码，其余为稠密向量编码。
视觉驱动检索器（5 款）
- 直接处理文档页面截图或布局元素图像，无需文本转化：
- 开源模型：DSE（wiki-ss）、DSE（docmatix）、ColPali；
- 微调模型：基于 MMDocIR 训练集微调的 DPR-Phi3 与 Col-Phi3（均基于 Phi3-Vision 构建）；
- 编码策略：ColPali、Col-Phi3 为 token 级编码，DSE、DPR-Phi3 为稠密向量编码。
实验设置
（1）评估指标
- 召回率（Recall@k）：衡量 Top-k 检索结果中包含真实证据的比例，页面级通过页面索引匹配，布局级通过边界框重叠度计算；
- 效率指标：存储开销（GB）、索引时间（分：秒）、检索延迟（分：秒），评估不同检索器的部署可行性。
（2）实验配置
- 文档处理：页面级检索中，文本检索器使用 OCR-page（OCR 文本 + 自然文本）或 VLM-page（VLM 生成文本 + 自然文本），视觉检索器直接使用页面截图；布局级检索中，文本检索器处理 OCR-text 或 VLM-text，视觉检索器使用裁剪后的布局元素图像或混合输入（文本 + 图像）
- 硬件环境：实验采用 GPU 集群，文本检索批量大小为 256，图像检索批量大小为 4
## 6.核心实验结果分析
### 页面级检索性能
核心结果
视觉驱动检索器整体显著优于文本驱动检索器，具体表现如下：
- 顶尖视觉检索器 Col-Phi3（微调后）平均 Recall@k（k=1/3/5）达 82.2/83.0，远超文本检索器中最优的 ColBERT（72.3/72.3）
- 视觉检索器中，微调模型（DPR-Phi3、Col-Phi3）性能优于开源模型（ColPali、DSE），证明 MMDocIR 训练集的有效性
- 文本检索器中，使用 VLM-text 的版本比 OCR-text 平均提升 6.3 个百分点，因 VLM-text 能保留表格结构、图像语义等 OCR 丢失的信息
- token 级编码检索器（ColBERT、ColPali）在 Recall@1 上优于稠密向量编码检索器，但存储开销是后者的 10 倍以上（ColPali 索引需 10GB，DSE 仅需 0.24GB）
领域差异分析
- 政府文档、法律文档等文本密集型领域：文本检索器与视觉检索器性能差距较小
- 宣传册、教程等视觉密集型领域：视觉检索器优势显著，Col-Phi3 比 ColBERT Recall@k 提升超 15 个百分点
- 财务报告、学术论文等表格 / 图表密集型领域：视觉检索器能更好捕捉表格结构与图表趋势，性能领先文本检索器 10-12 个百分点
### 布局级检索性能
核心结果
布局级检索任务更具挑战性，但视觉检索器仍保持优势：
- 视觉检索器 Col-Phi3 平均 Recall@k 达 63.3，文本检索器 ColBERT 为 63.7（接近但仍略低），因布局级元素文本信息更集中，OCR/VLM-text 损失较小
- VLM-text 在布局级检索中提升更显著，文本检索器使用 VLM-text 比 OCR-text 平均提升 9.8 个百分点，尤其在表格、图像类布局元素上提升明显
- 直接布局检索 vs 级联检索（先页面检索再布局检索）：级联检索在部分模型组合中性能略有提升（如 Col-Phi3+ColBERT Recall@10 达 65.4），但受页面检索错误传导影响，整体优势不显著
### 关键发现总结
1.视觉驱动检索器优势显著：在页面级检索中平均 Recall@k 比文本驱动检索器高 10.7 个百分点，证明保留原始视觉信息与布局结构对多模态检索至关重要
2.VLM-text 优于 OCR-text：文本检索中，VLM 生成的描述文本能更全面保留多模态元素的语义与结构，大幅提升检索性能
3.检索粒度影响性能：布局级检索因定位更精准，整体召回率比页面级低 15-20 个百分点，对检索器的精准定位能力要求更高
4.准确性与效率权衡：token 级编码检索器准确性略高，但存储与计算开销显著大于稠密向量编码检索器，实际部署需根据需求选择
## 7.局限性与未来方向
### 局限性
1. 训练集布局标注不完整：7 个训练子集中有 3 个因布局复杂未完成布局级标注，依赖后续优化标注流程
2. 视觉检索器文本处理能力不足：视觉检索器在纯文本段落检索上性能低于文本检索器，因训练未充分覆盖文本 - 文本检索场景
3. 未支持多语言与超长文档：当前数据集以英文为主，未覆盖 100K+token 的超长文档检索场景
4. 缺乏动态检索评估：未评估检索器在文档更新场景下的增量检索能力
### 未来方向
1. 完善训练集布局标注：利用先进 VLM 工具自动化标注复杂布局，扩大布局级训练数据规模
2. 优化视觉检索器：通过文本 - 图像联合训练，提升视觉检索器对纯文本内容的检索能力
3. 扩展数据集场景：支持多语言、超长文档、动态更新文档等更贴近真实应用的场景
4. 探索高效检索方案：研究混合检索架构（文本 + 视觉），平衡准确性与效率
5. 深化跨模态推理：构建需跨模态信息融合的复杂查询，推动检索器从 “信息定位” 向 “知识整合” 演进
## 8.结论
MMDocIR 基准数据集的提出填补了多模态长文档检索评估的空白，其支持的 “页面级 + 布局级” 双任务为全面衡量检索系统性能提供了标准化工具。实验结果明确了视觉驱动检索器在多模态检索中的核心优势，验证了 VLM 生成文本对文本检索的提升作用，同时 量化 了不同检索器的效率差异，为研究与部署提供了关键参考。
论文的核心结论是：多模态长文档检索的性能提升关键在于充分利用视觉信息与布局结构，视觉驱动检索器虽计算开销更高，但在准确性上显著优于文本驱动检索器；实际应用中需根据检索粒度、资源限制选择合适的检索方案。MMDocIR 的 开源 将推动多模态长文档检索领域的标准化研究，加速技术落地。
## 补充
### 9.布局级（Layout-level）标注是如果构建的
布局级可以理解为直接理解为一种“以 Query 为条件的目标检测（Query-conditioned Object Detection）”。模型不仅要找到对应的页面，还要在这一页预测出一个 Bounding Box (边界框)，准确框住能回答问题的那个证据区块。
为了实现如此细粒度且大规模的数据集，MMDocIR 的构建并没有采用纯人工从零框选的方式，而是采用了一套“自动化解析 + 大模型生成 + 人工精调验证”的流水线。
具体的标注实现步骤
1. 版面预解析与切分（获取所有候选 Bounding Box）
首先，使用文档解析工具（如 PDF 解析器或版面分析视觉模型），对原始长文档的每一页进行全面的物理版面分析。这一步会把页面拆解成一个个独立的版面元素（Layout Elements），如段落（Paragraph）、图（Figure）、表（Table）、公式（Equation）等，并记录下每一个元素的精确 Bounding Box 坐标 [x1, y1, x2, y2]。此时，页面上所有的元素都成了后续检索的“候选框”。
2. 基于特定元素生成问答对（建立 Query 与 Box 的天然映射）
为了解决人工标注成本过高的问题，研究人员采用了一种逆向生成的策略。他们会把上一步提取出来的某一个（或某几个）特定元素（例如一张复杂的架构图，或者一段关键结论文字）输入给多模态大模型（如 GPT-4V），指令模型专门针对这个元素的内容生成一个相关的用户查询（Query）和答案（Answer）。
因为问题本来就是根据这个特定的 Bounding Box 内部的信息生成的，这样就自动获得了“Query -> 目标 Bounding Box”的 Ground Truth 映射。
3. 全局负样本构建（形成长文档检索上下文）
有了 Query 和对应的 Bounding Box 后，这篇长文档中的其他所有页面，以及目标页面上的其他所有不相关的 Bounding Box（比如同一页上的其他段落），就自动成为了这个 Query 的难负样本（Hard Negatives）。这就构建出了真实的“大海捞针”检索场景。
4. 专家清洗与验证集精标（确保评测标准的绝对严谨）
虽然训练集可以依赖自动化生成，但对于用于评测的验证集（Validation set）和测试集（Test set），必须保证极高的质量。领域专家（人类标注员）会介入，对生成的问答对和 Bounding Box 进行严格的核查：
- 检查问题是否具有明确的指向性。
- 检查绑定的 Bounding Box 是否是回答该问题的唯一且充分的证据。
- 如果一页中有多个元素组合才能回答问题，专家会手动合并或新增 Bounding Box。
通过这种机制，数据集不仅保证了数量（数万个训练样本），也确保了验证集中那 2,638 个布局级标注是高度精准的“证据框”，而不仅仅是普通的“版面结构框”。
### 10.如何评估这种布局级检索的准确率的
因为提到了 Bounding Box（边界框），熟悉计算机视觉（CV）的人第一时间想到的评估指标肯定是 IoU（交并比） 或者 mAP（平均精度均值）
但在 MMDocIR 中，对于布局级检索的评估，并没有采用 IoU 这类目标检测指标，而是采用了经典的信息检索（IR）排序指标（如 Recall@K、MRR 等）。
1. 为什么不用 IoU？（检测 vs. 检索）
在传统目标检测（如 YOLO）中，模型需要在一张图片上“从无到有”地回归出坐标框，所以必须用 IoU 来衡量预测框和真实框重合了多少。
但在 MMDocIR 定义的检索任务中，寻找 Bounding Box 并不是让检索模型去“画框”，而是把它做成了一个“从海量候选库中做单项选择题”的任务。
2. MMDocIR 的布局级评估流水线
根据论文的设定，评估布局级检索的具体流程如下：
#### 离线切分与建库（Offline Indexing）：
在检索发生之前，作者使用版面分析工具（MinerU）把所有的长文档提前切分成了数十万个独立的“布局元素”（段落、图片、表格等）。每一个元素都有自己固定的 Bounding Box 和唯一的 ID。接着，系统把这些切好的元素全部转换成向量（Vector Embeddings）存入数据库。
#### 在线相似度计算（Online Querying）：
当用户提出一个 Query 时，检索模型（无论是纯文本还是多模态视觉模型）会计算这个 Query 向量与数据库中所有数十万个布局元素向量的相似度得分（Similarity Scores）。
#### Top-K 排序输出：
系统根据得分从高到低排序，输出最相关的前 K 个布局元素。因为每个元素自带 Bounding Box，只要找到了对应的元素，也就等于输出了它的 Bounding Box。
3. 具体使用的评估指标
既然这是一个“从库里把正确的那个元素捞出来并排在前面”的任务，MMDocIR 就顺理成章地使用了标准的信息检索指标：
- Recall@K（召回率）：这是最核心的指标。系统会看模型给出的 Top-K（比如前 5 个或前 10 个）最相关的结果中，是否包含了那个 Ground Truth（带有正确 Bounding Box 的那个特定的图或段落）。如果正确答案在 Top-K 里，记为 1；否则为 0。
- MRR (Mean Reciprocal Rank，平均倒数排名)：这个指标用来衡量模型排名的“精准度”。如果正确的 Bounding Box 被排在了第 1 位，得分为 1；排在第 2 位，得分为 1/2；排在第 10 位，得分为 1/10。排名越靠前，得分越高。
- NDCG (归一化折损累计增益)：用来评估整体排序列表的质量，确保最相关的证据不仅被找到，而且被排在最前面。
总结来说：
MMDocIR 里的 Bounding Box 更多是作为版面元素的“身份证”和“确凿证据”。模型不需要自己去学习怎么精准画框（这是版面分析工具的活），模型的任务是证明自己能在一大堆已经画好框的切片中，精准地召回并排高那个能回答问题的唯一切片。
### 文本检索和视觉检索在多模态文档中的表现差异
在 MMDocIR 的实验评估中，核心结论非常明确：以 ColPali 为代表的“直接看图”的视觉驱动检索器，在性能上显著优于（Significantly Outperform）以 ColBERT 为代表的纯文本驱动检索器。
论文的实验数据在页面级（Page-level）和布局级（Layout-level）检索任务中都印证了这一点。以下是视觉驱动检索器之所以能实现“降维打击”的核心原因：
1. 传统 OCR 导致了严重的信息丢失与结构破坏
纯文本驱动检索器（如 ColBERT）在处理文档时，必须先经过 OCR（光学字符识别）或 PDF 文本解析引擎。然而，长文档中不仅有字，还有大量非结构化信息：
- 空间排版：多栏排版、侧边栏、复杂的嵌套表格。OCR 很容易把阅读顺序搞错，或者把表格变成一堆没有逻辑关联的碎字。
- 纯视觉元素：折线图的走势、架构图中模块的连接关系、或者是公司的 Logo。这些信息 OCR 完全无法提取。
- 而像 ColPali 这样的视觉模型，直接将文档页面作为一张图片（Image Patches）输入进视觉语言模型（VLM）中进行编码，100% 且无损地保留了原始的视觉线索、排版几何结构和字体粗细等特征。
2. 避免了“级联错误” (Cascading Errors)
文本驱动的检索往往需要一个复杂的流水线（Pipeline）：先用模型做版面分析 -> 对不同区域做 OCR -> 用小模型给图片生成描述（Caption） -> 最后再把所有文本拼起来向量化。这个过程中任何一步的错误都会累加。而视觉驱动模型是端到端（End-to-End）的，直接从像素到向量，没有中间商赚差价。
3. 一个反向证明：VLM-text 碾压 OCR-text
MMDocIR 论文做了一个非常有意思的对比实验：如果我们依然坚持用文本检索器，但是不用 OCR 提取的字，而是用 GPT-4o 这样的大模型去“看图说话”，把文档翻译成极其详细的文本描述（VLM-text），会发生什么？
结果显示，基于 VLM-text 的文本检索器性能远好于基于 OCR-text 的检索器。这从侧面证明了：不是文本检索模型（如 ColBERT）本身的匹配能力不行，而是 OCR 喂给它的文本太烂，错失了太多的“视觉-语义”细节。
公平地说：文本驱动检索器真的毫无优势吗？
并不是。论文在“效率考量（Efficiency Considerations）”部分指出，虽然 ColPali 这类模型在召回率上赢了，但它付出了巨大的资源代价。
像 ColPali 和 ColBERT 都使用了“Token 级晚期交互（Late Interaction）”技术来保证极高的细粒度匹配精度。但因为 ColPali 编码的是密集的图像 Patch（图块），它生成的索引存储空间（Index Size）和检索延迟可以达到普通文本向量模型的 10 倍左右。
总结来说：
如果是为了追求极致的准确率，尤其是处理包含大量财报、学术图表和复杂排版的长文档，直接看图的视觉模型（ColPali）是绝对的王者。但如果你的算力和存储资源极其受限，或者文档全是纯文字的网文，纯文本检索依然是性价比最高的选择。
