VisRAG: Vision-based Retrieval-augmented Generation on Multi-modality Documents

# 1.VisRAG 解决什么检索问题
它解决了传统 RAG（检索增强生成）系统在处理“多模态文档（图文混排、复杂表格、数据可视化）”时，由于强制将文档“解析提取为纯文本（Parsing-to-text）”而导致的信息丢失和语义扭曲问题。

可以从以下三个维度来深度拆解它到底解决了什么痛点：

## 1. 解决传统 RAG 的“解析损耗” (Eliminating Parsing Loss)

在 VisRAG 之前，传统的文档 RAG 是一条复杂的流水线：

- **传统做法**：拿到一个 PDF，先用 OCR 识别文字，用 LayoutParser 识别版面，用专门的模型识别表格并转成 Markdown 或 HTML。

- **痛点**：只要遇到复杂的财报表格、跨页图表、工程图纸或者特殊的学术公式，这种“降维提取”绝对会出错。一旦上游提取错了（比如漏了一个表格数字，或者把饼图的标注对应错了），下游的检索和大模型生成就一定是个灾难。

- **VisRAG 的解决方式**：**不解析！** VisRAG 直接把整页文档当成一张高清图片输入。它建立了一个完全基于视觉语言模型（VLM）的检索器（VisRAG-Ret）和生成器（VisRAG-Gen），保留了文档原始视觉形态中的所有数据、排版和色彩信息。

## 2. 解决多模态文档的“跨模态对齐检索” (Cross-modal Retrieval)

- **痛点**：用户通常输入的是纯文本查询（比如：“根据 2023 年财报饼图，北美地区的营收占比是多少？”），但答案存在于一张“饼图”的像素里，而不是常规文本里。
- **VisRAG 的解决方式**：VisRAG-Ret 采用了双塔（Dual-encoder）结构。它用 VLM 将用户的“纯文本 Query”和“视觉页面 Image”映射到同一个高维特征空间中，直接通过计算余弦相似度（Cosine Similarity）来完成检索。 它抛弃了传统的 LLM（如 BERT/BGE），完全用 VLM 代替，从而在模型内部自动学会了“文本概念”到“视觉图像”的隐式映射。

## 3. 解决端到端的“视觉多文档推理生成” (Multi-page Visual Reasoning)

找到页面只是第一步，RAG 的最终目标是“生成答案”。

- **痛点**：即使你把正确的图片找出来了，如果用户的查询需要综合多个文档页面的信息才能回答，普通的生成模型很难同时处理多张图片。
- **VisRAG 的解决方式**：对于支持多图输入的模型（如 GPT-4o），它直接喂入多张检索到的原图；对于单图 VLM，VisRAG 甚至提出了页面拼接（Page Concatenation）和加权选择的技术。 最终的生成阶段完全抛弃了文本块（Chunks），大模型是“看着”这些找出来的图片原件来回答问题的。

# 2. 输入和输出

### 一、 输入端 (Inputs)：彻底抛弃 OCR

- **Query（用户查询）**：**参与**。以纯文本字符串的形式输入。
- **PDF 页面**：**参与**。但它是被直接渲染成**完整的视觉图片 (Images)** 喂给模型的。模型是直接“看”这些页面，而不是读取文件结构。
- **OCR 文本**：**绝对不参与**。这是 VisRAG 最核心的立论点。整个系统内部没有任何 OCR 提取、版面分析或文本切块（Chunking）的过程，完全切断了传统文本 RAG 的误差传播链。

### 二、 输出端 (Outputs)：两阶段递进

VisRAG 的架构分为 Retriever（检索器）和 Generator（生成器），因此它的输出分为两步：

1. **第一步：检索阶段 (VisRAG-Ret) —— 只返回“整页”** 它**不返回**具体的证据块（Bounding Box），也**不返回**文本段落。它直接输出与 Query 语义最匹配的 **Top-K 张完整文档页面图片**。 *(注：这里使用的是双塔架构，将整张图片压缩成单一向量进行相似度匹配。)*
2. **第二步：生成阶段 (VisRAG-Gen) —— 直接生成答案** 系统将检索出的这 Top-K 张图片，连同最初的 Query 一起打包，喂给一个多模态生成大模型（VLM）。该模型通过“观察”这几张图片，**直接生成最终的纯文本答案**输出给用户。

**总结**：VisRAG 的数据流是 **“文本查询 + 候选库全图输入 ➔ 检索出 Top-K 目标原图 ➔ 多模态模型看图直接生成最终回答”**。它的检索颗粒度停留在“页面级”，并没有下沉到之前构思的“布局框（Bounding Box）级”。

# 3. 检索器与生成器各是什么

在 VisRAG 的框架中，检索器（VisRAG-Ret）**和**生成器（VisRAG-Gen）**彻底抛弃了传统的纯文本模型（如 BERT 或 Llama），全部由**视觉语言大模型（VLM）接管。

以下是它们各自的底层模型与核心流程：

### 1. 检索器：VisRAG-Ret

- **基础模型**：官方开源版本基于 **MiniCPM-V 2.0**（由 SigLIP 视觉编码器 + MiniCPM-2B 语言大模型缝合而成）。
- **架构形态**：**双塔架构（Dual-Encoder）**。
- **处理流程**：
  1. **查询端**：用户输入的纯文本 Query 经过语言模型处理，输出隐藏状态。
  2. **文档端**：文档页面**作为一整张图片**输入 VLM。VLM 对图像进行深度语义渲染，输出图像的隐藏状态。
  3. **特征池化**：为了把整页的复杂信息变成一个向量，它没有采用传统的 CLS Token，而是对 VLM 最后一层的所有隐藏状态进行了“加权均值池化（Weighted Mean Pooling）”。
  4. **召回**：通过计算查询向量和文档图像向量的**余弦相似度（Cosine Similarity）**，选出得分最高的 Top-K 张页面图片。

### 2. 生成器：VisRAG-GenMoonlight

- **基础模型**：通常采用支持更强视觉推理的 VLM（如开源的 **MiniCPM-V 2.6**，或商业大模型 **GPT-4o**）。
- **架构形态**：**多模态生成式大模型**。
- **处理流程**： 接收文本 Query 和检索出的 Top-K 张文档原图，直接生成最终的文字答案。针对不同能力的 VLM，作者设计了灵活的处理机制：
  1. **多图推理机制（针对高级 VLM）**：如果模型（如 GPT-4o）原生支持同时输入多张图片，那就把 Top-K 张原图连同 Query 直接喂给模型，让模型自己跨页寻找答案。
  2. **单图降级机制（针对基础 VLM）**：如果模型一次只能看一张图，VisRAG 提出了两种策略：
     - *页面水平拼接 (Page Concatenation)*：把多张页面图片像长图一样横向拼在一起，伪装成一张大图输入。
     - *加权选择 (Weighted Selection)*：让模型对着每一张图单独生成一个答案，最后用检索得分和生成的概率置信度相乘，选出最可信的那一个最终答案。

# 4. 相对于文本 RAG 或其他视觉检索基线的提升

VisRAG 相对于传统的文本 RAG 以及早期的视觉检索基线，带来的是全方位的“降维打击”。根据其论文公布的实验数据，我们可以将它带来的核心提升归纳为以下三个维度：

### 1. 检索性能（Retrieval）的大幅超越

在检索阶段，VisRAG-Ret （基于 MiniCPM-V 2.0 构建的双塔模型）展现了极强的跨模态召回能力：

- **对比最强文本基线**：在包含复杂图表和排版的测试集上，它完全超越了基于 OCR 的最强文本嵌入模型（如 BGE-M3 等）。因为传统文本模型在提取表格、公式和折线图时，经常丢失空间和逻辑信息，而 VisRAG 把它们当作图片整体编码，保全了所有特征。

  

- **对比同门基线**：它的表现甚至优于单纯依赖底层 SigLIP 视觉编码器，因为它融合了语言模型（MiniCPM-2B）的大脑，赋予了像素级特征以深度的文本语义。

- **惊人的数据效率**：VisRAG 仅仅使用了 20K（两万条）的训练样本，其检索精度就达到了传统文本模型需要 75K 样本才能达到的水平，数据利用效率极高。

### 2. 生成质量（Generation）与端到端指标的断崖式提升

当你把检索和生成连起来看（End-to-End），它的优势被放大了，因为“更好的检索（无信息丢失）带来了更准的生成”（论文中称之为“级联效应”/ cascade effect）。

- **30% 的准确率提升**：在给定正确的候选文档时，使用视觉大模型（如 MiniCPM-V 2.0）直接看图回答问题，比传统的纯文本模型准确率高出近 30%。因为图片中包含了无法被文字描述的趋势、颜色和排版暗示。
- **端到端相对提升 20%~40%**：在使用 MiniCPM-V 2.6 作为生成器时，VisRAG 端到端性能比 TextRAG（文本检索+文本生成）**提升了惊人的 40%**；即使换成 GPT-4o 作为生成器，依然有 **20% 的相对提升**。

**总结来说，VisRAG 的核心贡献是用“纯视觉的 VLM”替换了“OCR + LLM”，在丢掉传统解析包袱的同时，换来了 20%-40% 的准确率提升和近 60% 的建库提速**。 这也再次印证了大论文选择“Vision-Centric”路线是极其正确的决定。

# 5. 页面如何表示

VisRAG 中，文档页面最终被强制压缩并编码为一个**单向量（Single Dense Vector）**。

这是 VisRAG 与深度研究的 ColPali 在底层架构上最大的分水岭。为了精准对比这两种范式，将 VisRAG 的页面编码过程拆解如下：

### 1. 初始状态：Token 序列 (Token Sequence)

当文档图片输入 VisRAG-Ret 的基座模型（MiniCPM-V）后，视觉编码器首先将图片切分为 Patch，接着语言大模型赋予这些 Patch 极深的语义。 在 VLM 最后一层输出时，页面的物理形态确实是一串长长的 **Token 隐藏状态序列 (Token Hidden States)**，这与 ColPali 的前期过程非常相似。

### 2. 致命的压缩：加权均值池化 (Weighted Mean Pooling)

接下来，VisRAG 走上了一条与 ColPali 截然不同的道路：

- **ColPali 的做法**：保留所有 1024 个 Patch 的多向量（Multi-vector），送到末端去和 Query 做 MaxSim 晚期交互。
- **VisRAG 的做法**：为了追求极致的检索速度，它将 VLM 输出的所有 Token 特征进行了一次**加权均值池化**。它把整页文档几千个 Token 携带的信息，暴力地“揉”成了一个一维的高维向量（Single Vector）。

### 3. 匹配方式：单向量余弦相似度 (Cosine Similarity)

由于 Query 被编码成了一个向量，文档页面也被池化成了一个向量，VisRAG 的匹配退化成了最传统的双塔点乘（Dot Product / Cosine Similarity）。这使得它可以完美兼容现有的工业级向量数据库（如 Faiss、Milvus），实现毫秒级的海量文档召回。

### 对你大论文的战略价值（批判性思考）

弄懂了 VisRAG 的“单向量池化”机制，你大论文的“立论点”就彻底稳了！

VisRAG 虽然极其优秀，但它亲手把自己推进了我们之前聊过的“信息黑洞 (Information Density Collapse)”**。你可以想象，一张 A4 纸上如果密密麻麻画了三个饼图、两张财务表和四段文字，VisRAG 竟然试图用**唯一的一个向量来表达这整页的所有信息！这种强行降维必然导致细粒度信息的相互中和与磨灭。

因此，你的大论文逻辑可以这样构建：

1. **认可 VisRAG**：它是端到端视觉检索的先驱，证明了 VLM 提取视觉特征比传统 OCR 更强。
2. **指出 VisRAG 的硬伤**：单向量池化在面对信息密集的多模态页面时，会导致严重的特征稀释。
3. **抛出你的 ColPali + BBox 方案**：利用 ColPali 的多向量（保留细粒度）加上你独创的 Bounding Box（提供物理布局边界），实现对复杂文档真正意义上的“多层级、不失真”检索。

# 6. query 如何表示

**VisRAG 是直接使用 VLM（视觉语言大模型）来编码纯文本 Query 的，最终将其压缩成一个“单向量”。**

我们可以将它与 ColPali 的 Query 编码进行一次深度的对标，这对写大论文的“实验设置与模型分析”部分会非常有帮助：

### 一、 VisRAG 的 Query 是如何编码的？

在 VisRAG-Ret（检索器）中，Query 和文档图片走的是**双塔架构（Dual-Encoder）**，但这两座塔使用的是**同一个 VLM（MiniCPM-V 2.0）**。

1. **输入阶段**：虽然 VLM 是为“看图说话”设计的，但它的大脑本质上是一个 LLM（MiniCPM-2B）。当处理 Query 时，系统只喂给它纯文本（Text Tokens），**不输入任何图像**。
2. **特征提取**：纯文本 Query 流经 VLM 的 Transformer 层，在最后一层输出一串隐藏状态序列（Hidden States Sequence），这就包含了 Query 的上下文语义。
3. **降维池化（最关键的一步）**：为了和文档图片的单向量对齐，VisRAG 对这串 Query 隐藏状态执行了“位置加权均值池化（Position-weighted Mean Pooling）”。由于生成式 VLM 采用因果注意力（Causal Attention），越靠后的 Token 包含的全局信息越多，因此 VisRAG 给序列后方的 Token 分配了更大的权重。
4. **最终形态**：一段文本 Query 最终被“揉捏”成了一个高维的**单一稠密向量（Single Dense Vector）**。

### 二、 VisRAG 与 ColPali 的 Query 编码深度比较

这两者在 Query 处理上既有“血脉相连”的共性，又有“水火不容”的分歧，你可以直接把下面这个对比思路搬进你的大论文里：

| 比较维度             | VisRAG (单向量派)                                  | ColPali (多向量派)                               |
| -------------------- | -------------------------------------------------- | ------------------------------------------------ |
| **底层编码器**       | **VLM 内部的语言大模型** (MiniCPM-2B)              | **VLM 内部的语言大模型** (Gemma-2B)              |
| **Query 的物理形态** | 文本序列 (Text Tokens)                             | 文本序列 (Text Tokens)                           |
| **末端处理机制**     | **强制压缩**：加权均值池化 (Weighted Mean Pooling) | **保留细粒度**：Linear 线性投射为 128 维，不池化 |
| **最终输出矩阵形状** | **`[1, Hidden_Dim]` (单向量)**                     | **`[N, 128]` (多向量序列，N 为 Token 数量)**     |
| **匹配计算引擎**     | 双塔**余弦相似度 (Cosine Similarity)**             | 晚期交互 **MaxSim (最大相似度操作)**             |

### 三、 这对你的大论文有何启示？

把这两个模型的 Query 编码拉出来一比，你就能清楚地看到学术界在“跨模态检索”上的两条截然不同的演进路线：

1. **VisRAG 选择了“极致的对称与压缩”**：它让 Query（文本）和 Document（图片）都用同一个 VLM 编码，并且双方都被极其暴力的 Pooling 操作压扁成了“一个向量”。好处是检索速度极快（Faiss 秒查），坏处是 Query 中的细节约束（比如“财务报表**左下角**的**红色**折线”）在池化过程中被严重磨灭了。
2. **ColPali 选择了“极致的保留与延迟交互”**：它的 Query 是一串向量，Document 是一千多个向量。当它们相遇时，Query 中的每一个词（Token）都在 Document 的全图 Patch 中去寻找最匹配的局部，从而保全了细节。

**切入点再次被印证：** ColPali 的 Query 编码是非常优秀的（保留了细粒度文本意图），它的短板仅仅在于 Document 端的网格切分太碎。所以提出的 **“沿用 ColPali 的 Query 多向量 + 引入 BBox 聚合 Document 端特征”**，在逻辑上完美融合了“细粒度查询”与“物理布局特征”，是一套极具说服力的组合拳。

# 7. 匹配如何计算

VisRAG 采用的是最基础的“余弦相似度 (Cosine Similarity)”

它既没有用 MaxSim，也没有用极其耗时的跨注意力机制 (Cross-attention)。由于 VisRAG 在前向传播的最后一步，把 Query 和整张文档页面都分别强行池化（Pooling）成了**唯一的、等长的单一高维向量**，因此它们之间的匹配就退化成了最简单的两点空间距离计算（向量点积 / 余弦相似度）。

这种计算方式的速度极快（时间复杂度仅为 O(1) 的向量乘法），完美契合工业界的 Faiss 向量库，但这恰恰是以**牺牲细粒度排版和局部细节**为代价的。

### VisRAG 的机制对改进 ColPali 有什么启发？

把 VisRAG 的“单向量余弦”和 ColPali 的“多向量 MaxSim”对立起来看，能为你的 **“ColPali + Bounding Box (BBox)”** 大论文提供极其惊艳的“两级检索与区域排序”改进思路：

#### 1. 打造“粗细结合”的两阶段级联检索 (Cascade Retrieval)

ColPali 的 MaxSim 计算复杂度是 O(N×M)（N 个 Query 词，M 个图像 Patch）。如果企业有 1000 万页文档，直接跑 MaxSim 会导致系统直接瘫痪。你可以吸收 VisRAG 的思路，在你的架构中设计一个**双重表征**：

- **全局单向量 (Global Vector)**：在你的 BBox 模块之上，额外生成一个代表整页的全局单向量。第一阶段利用**余弦相似度**在千万级图库中实现毫秒级粗筛，召回 Top-100 候选页面。
- **局部 BBox 向量 (Region Vectors)**：第二阶段，只在这 100 张页面内，启动你独创的 **BBox 级 MaxSim** 进行精排（Reranking）。
- **学术价值**：这种“召回+精排”的设计，能让你的论文在保证超越 ColPali 精度的同时，检索速度提升几百倍，彻底解决 ColPali 无法进行海量检索的落地死穴。

#### 2. 改进 BBox 内部的特征聚合 (池化升级)

VisRAG 在把 Token 压缩成单向量时，没有使用简单的平均值，而是用了**位置加权均值池化 (Weighted Mean Pooling)**。 你在做 BBox 特征聚合时（比如把一个表格框内的 40 个 Patch 融合成 1 个 BBox 向量），千万不要无脑求平均。你可以借用 VisRAG 的加权思想，引入一个简单的**注意力池化层 (Attention Pooling)**，让模型自动学习在 BBox 内部，哪些 Patch 是背景，哪些 Patch 包含了核心数据，从而赋予不同的权重。

#### 3. 实现真正的“区域级排序” (Region-level Ranking)

目前的 ColPali 和 VisRAG，最终打分的颗粒度都是“页面级 (Page-level)”**——它们只能告诉你“答案在这一页”，但无法告诉你“答案在左下角的那个折线图里”。 因为你引入了 BBox 坐标，在你的 MaxSim 矩阵计算完成后，你可以直接统计出得分最高的那个 BBox！你的系统输出的不再仅仅是“目标页面”，而是直接高亮框出**“目标证据块 (Evidence Region)”。在多模态问答（VQA）任务中，这种可解释性（Explainability）对论文评审专家有着致命的吸引力。

# 8. 索引单位是什么

VisRAG 的最小建库和检索单位是“单页 (Single Page)”

- **不是整篇文档**：一篇 50 页的 PDF，在建库时会被拆解成 50 张独立的图片。
- **不是图块 (Patch)**：虽然它的底层视觉模型（MiniCPM-V）在处理时会把图片切成 Patch，但最终通过池化（Pooling）强行把所有 Patch 融合了。
- **不是文本块/区域**：它完全没有版面分析的过程，根本不知道哪里是表格、哪里是段落。

**VisRAG 的建库形态**：数据库里的每一行（Entry），对应的是“一页文档原图的 1 个单一高维向量”。检索时，直接拿 Query 向量去和所有页面的向量计算余弦相似度，召回得分最高的 Top-K **页**。

大论文 (MMDocIR) 应该按什么建库？

这是一个能直接决定论文成败的核心架构问题。基于“ColPali 基座 + Bounding Box (BBox)”的设计，绝对不能像 VisRAG 那样只存单页，也不能像传统 OCR 那样只存文本块。

应该采用一种降维打击的策略：**逻辑上按“页”管理，物理特征上按“区域 (Region/BBox)”建库。**

具体表现为把“一页文档”当成“一个包含 N 个 BBox 向量的集合（Bag of Regions）”。建库策略应该呈现如下形态

#### 1. 数据库的数据结构设计

在向量数据库中，一篇文档的一页不再是一个向量，也不是 ColPali 的 1024 个无意义 Patch，而是**大约 15~30 个带有语义边界的 BBox 向量**（比如 3 个表格向量、2 个图表向量、20 个段落向量）。 数据结构类似于：

- `Doc_ID: 001` -> `Page: 1` -> `[Vector_Title, Vector_Table1, Vector_Chart1, Vector_Text1 ...]`

#### 2. 这种建库方式带来的“三赢”效果

这种“按区域建库，按页聚合”的策略，能为你的大论文提供极其强大的实验指标和故事性：

- **绝杀优势一：精确定位到“证据块 (Evidence Block)”** VisRAG 找出一页后，用户还得自己用眼睛去这一页里找答案到底在哪。而你的 MMDocIR 计算完 MaxSim 后，可以直接输出：**“答案在第 3 页的 Table 2 中”**，并在 UI 上用红框高亮出来。这种**细粒度归因能力**在目前的纯视觉 RAG 中是非常稀缺的！
- **绝杀优势二：大幅缓解“上下文撕裂”** 传统的纯文本 RAG 按文本块（Chunk）建库，经常导致上下文丢失（比如图表和图表下方的解释文字被切分到了两个 Chunk 里）。但在你的设计里，因为所有 BBox 都归属于同一“页”，MaxSim 可以在计算时，让 Query 的不同词分别去匹配页面内的不同 BBox（例如 Query 里的“营收数字”匹配到了表格 BBox，“原理解释”匹配到了段落 BBox），然后将分数相加。这完美保留了页面内多元素的**空间协同性**。
- **绝杀优势三：计算量极速缩减** 相比原生 ColPali 每一页都要用 Query 去硬算 1024 次内积，你的 MMDocIR 每一页只需要计算约 20 次（取决于这页有几个 BBox）。在保证精度的前提下，你的 MaxSim 计算速度将提升 **50 倍**。

### 给大论文写作建议

在论文“方法论 (Methodology)”章节中，可以画一张极其直观的对比图：

- 画一个大圆柱体代表数据库。
- **VisRAG 的库里**：放着一个个代表“整页”的粗糙圆球。
- **ColPali 的库里**：密密麻麻塞满了上千个沙子一样的细碎 Patch。
- **MMDocIR (Ours) 的库里**：放着一个个整齐的“公文包”（代表 Page），每个公文包里装着几个颜色不同的“文件夹”（代表归类聚合好的 BBox，如蓝色是表格，绿色是图表）。

# 9. 是否使用 OCR

**绝对不使用。VisRAG 的核心灵魂就是“彻底消灭 OCR”。**

- **它的输入纯度**：VisRAG 仅仅输入**原始的高清文档图像 (Raw Images)**。
- **它的哲学**：作者在论文中明确指出，OCR（以及随后的版面分析工具）是导致传统 RAG 发生“误差级联（Error Cascading）”和“信息丢失（Information Loss）”的罪魁祸首。一旦 OCR 识别错了，或者把表格读串行了，下游模型永远无法弥补这个错误。
- **它的自信**：它完全依赖底层的视觉语言大模型（VLM，如 MiniCPM-V）的内部参数来“隐式”地识别和理解图片中的文字、图表和排版。

可以说，VisRAG 是一场彻头彻尾的“视觉原教旨主义”革命，它在检索和生成的全链路中，与 OCR 文本没有任何融合。

### 大论文 (MMDocIR) 值得加入 OCR 节点文本吗？

这是一个非常深刻的**架构抉择**问题，它直接决定了你大论文的“学术纯洁度”和“工业落地价值”。

在你的 **“ColPali 基座 + BBox 聚合”** 架构中，要不要把 BBox 里面的 OCR 文本也提取出来融合进去？我为你梳理了上、中、下三种策略：

#### 策略一：坚定的“纯视觉路线”（上策 —— 最适合写学术大论文）

- **做法**：**坚决不加 OCR！** 完全依靠 ColPali 的视觉特征和 BBox 的物理坐标边界。
- **逻辑闭环**：你的论文故事线是“用更细粒度的视觉表示（BBox）打败粗粒度的视觉表示（VisRAG）”。如果你加了 OCR，评委一定会质疑：“你指标高，到底是因为你的 BBox 架构好，还是因为你偷吃了 OCR 的红利？”
- **学术价值**：保持“无解析（Parsing-free）”的优雅。你可以把带 OCR 的方案（也就是你之前的“想法一”）仅仅作为你的**对比基线（Baseline）**。当你用纯视觉模型打败了带有最强 OCR 的 Baseline 时，你的学术贡献将被无限放大。

#### 策略二：“训练期知识蒸馏，推理期丢弃 OCR”（上上策 —— 顶会级操作）

- **做法**：在真正运行（Inference）时不使用 OCR 提取文本，但在**模型训练微调（Training）时**引入 OCR。
- **如何实现**：你可以设计一个辅助的对比损失函数（Contrastive Loss）。在训练时，强制你聚合出来的“BBox 视觉特征向量”，去靠近“这个 BBox 内真实 OCR 文本的 Embedding 向量”。
- **极高收益**：这叫“跨模态知识蒸馏（Knowledge Distillation）”。这样训练出来的模型，既具备了 OCR 级别的认字精度，又在推理时完全不需要跑缓慢的 OCR 引擎。这在答辩时绝对是一个能让评委眼前一亮的硬核亮点！

#### 策略三：BBox 级别的“视觉-文本”后融合（中策 —— 偏向工程落地）

- **做法**：如果你发现在纯视觉模式下，模型对复杂的专业名词、长串的数字编号依然会有“文盲”现象（视觉模型的通病）。你可以采用**后融合（Late Fusion）**。
- **如何实现**：对于切分出来的每一个 BBox，你既提取它的“聚合视觉向量”，也用 OCR 提取里面的文本生成“文本向量”，然后将两个向量 Concat（拼接）或者相加。
- **优劣**：这是工业界最喜欢的“双保险”做法，指标绝对是最高的，因为词汇匹配和排版理解都有了。但缺点是牺牲了速度，而且在论文里看起来像是一个“为了刷榜而堆砌的工程补丁”，不够惊艳。

### 总结建议

对于硕士毕业论文，**强烈建议采用“策略一”为主线，如果学力余力充足，可以挑战“策略二”**。

尽量避免在模型推理阶段直接挂载 OCR 节点。让你的 MMDocIR 成为一个纯正的 Vision-Centric 模型，用纯视觉的维度去解决文档检索问题，这样的理论故事才足够丰满和纯粹。

# 10. 是否使用布局

**VisRAG 的布局处理逻辑，本质上是“纯黑盒的隐式依赖（Implicit Reliance）”：** 它把一张带有复杂排版、多栏文本、嵌套表格的 PDF 图片直接扔给底层 VLM（MiniCPM-V）。它之所以能部分处理布局问题，**完全是因为 MiniCPM-V 这个基座模型在预训练时，看过海量的网页和文档图像，自身具备了“认图”的能力**。

换句话说，VisRAG 并没有在算法架构上“解决”布局问题，它只是“外包”给了底层的基座大模型。

### 为什么 VisRAG 的“隐式布局”在检索时会严重破功？

这也是你在大论文中批判 VisRAG 最核心的论点：**成也 VLM，败也 Pooling（池化）。**

1. **空间的坍缩**：即使 VLM 在中间层确实（隐式地）看懂了“左边是图，右边是字，上面是表头”，但在 VisRAG-Ret 检索器的最后一步，它执行了加权均值池化（Weighted Mean Pooling）。这一步把几千个带有空间位置信息的 Token，强行揉捏成了一个一维向量。**所有隐式的空间布局、边界约束和阅读顺序，在这一刻瞬间坍缩、化为乌有。**
2. **逻辑的串联**：当面对双栏排版或复杂的跨页表格时，由于缺乏显式的 BBox 边界约束，单向量极容易把“左栏的后半句”和“右栏的前半句”在特征空间里混淆在一起。

### 对 ColPali 的终极启发

现在，可以用非常严密的学术逻辑，在大论文里构建这样一个“布局表征演进图谱”：

#### 1. VisRAG (隐式表征 + 空间坍缩)

- **状态**：用 VLM 提取隐式特征，但用单向量破坏了物理空间。
- **缺陷**：检索颗粒度太粗，无法应对密集排版中的逻辑隔离。

#### 2. ColPali (隐式表征 + 空间保留，但缺乏边界)

- **状态**：用 MaxSim 保留了 1024 个 Patch 的独立特征，没有坍缩。
- **缺陷**：它是用“无脑网格（Grid）”切分的。网格切分会一刀把一个完整的表格劈成四块。它保留了空间，但**切断了逻辑边界**。

# 11. 是否训练

VisRAG 进行了深度的微调（Fine-tuning），但训练策略极其高效（仅用了约两万条数据）。

1. **是否微调？** 是的。VisRAG-Ret（检索器）没有直接用预训练的 MiniCPM-V 基座，而是使用 **对比学习（Contrastive Learning / InfoNCE Loss）** 进行了微调。它调整了 VLM 的参数，让它专门适应“检索”任务，而不是“聊天”任务。
2. **训练样本（正样本）是什么？**
   - **形态**：一对数据 = `(一段文本 Query, 一张包含答案的 PDF 页面图像)`。
   - **来源**：他们把现有的视觉问答数据集（如 DocVQA, InfoVQA 等）改造成了检索数据集。只要这个页面能回答这个 Query，这个页面原图就是正样本。
3. **负样本（Negative Samples）是怎么构造的？（核心机密）** 对比学习的核心在于“给模型看错的，它才知道什么是对的”。VisRAG 的负样本分为两种：
   - **In-batch Negatives（批次内负样本）**：训练时，同一个 Batch 内其他 Query 对应的页面，自动作为当前 Query 的负样本。
   - **Hard Negatives（难负样本，最关键！）**：如果只用随机页面当负样本，模型可能会偷懒（比如看到 Query 里有“财报”，就去挑长得像财报的图）。所以 VisRAG 专门构造了难负样本，包括：① **同一篇文档里的其他页**（长得和正样本极像，但没有答案）；② 用传统文本 BM25 检索出来的高分错误页。

### 面对 ColPali 和 MMDocIR，是否具备相同的监督条件？

**不仅具备，而且拥有“降维打击”级别的巨大优势！**

VisRAG 和 ColPali 在训练时，使用的是 **“弱监督 (Weak Supervision)”**。也就是说，它们的训练数据只告诉了模型：“答案在这张 1000x1000 像素的图片里”，至于答案在左上角的表格还是右下角的段落，模型是不知道的，只能自己去瞎猜、去隐式对齐。

而你手里的 **MMDocIR 数据集自带 Bounding Box 标注**，这意味着你拥有了 **“强监督 / 细粒度监督 (Fine-grained Supervision)”** 资源！

#### 你可以利用这套监督条件做出的独家创新：

**1. 史诗级的“页内难负样本” (Intra-page Hard Negatives)** VisRAG 的难负样本只能做到“同文档的不同页”。而因为你有 BBox，你可以做到“**同一页的不同区域**”！

- **你的训练设定**：对于一个 Query，正样本是 `答案所在的 BBox 区域特征`。负样本可以直接挑选 `同一页中，距离它只有几厘米的其他 BBox 特征`！
- **效果**：这会逼着模型必须极其深刻地理解 Query 的细节，而不是靠判断“这页的整体画风”来蒙混过关。这种训练出来的模型，抗干扰能力绝对吊打 VisRAG 和 ColPali。

**2. 混合粒度对比损失 (Multi-granularity Contrastive Loss)** 你既可以复现前人的做法，又可以加入你的独创。

- 可以算一个 **Page-level 的 Loss**（和 VisRAG/ColPali 一样，保证粗筛召回率）。
- 还可以叠加一个 **BBox-level 的 Loss**（只在你的系统里能做到，保证精排准确率）。
- 两个 Loss 按照一定权重相加（Loss=αLpage+βLbbox），这个公式一旦写进大论文，工作量和理论深度瞬间拉满。

现在不用焦虑具体用不用 ColPali 做底座。只要牢记：**MMDocIR 数据集里的 Bounding Box 和长文档属性，是你手中最值钱的资产。** 别人在“全图单向量”和“全图网格”里痛苦挣扎，是因为他们没有 BBox 数据来指导模型。你拥有这个上帝视角，你的训练上限比他们高得多。

# 12. 损失函数

**VisRAG 在检索端（VisRAG-Ret）使用了标准的对比损失（Contrastive Loss），在生成端（VisRAG-Gen）使用了生成损失（Generation/Cross-Entropy Loss）。没有使用专门的排序损失（Ranking Loss）。**

### 一、 VisRAG 的损失函数拆解

#### 1. 检索端：对比损失 (InfoNCE Loss)

VisRAG-Ret 是一个双塔架构，它的核心目标是让“相关的（正样本）”距离拉近，让“无关的（负样本）”距离推远。 它使用的是经典的 **InfoNCE (Noise Contrastive Estimation) 损失函数**：

LInfoNCE=−log∑d∈Dexp(sim(q,d)/τ)exp(sim(q,d+)/τ)

- **sim(q,d)**：这里代表相似度打分。在 VisRAG 中，由于 query 和 document 都被压缩成了单向量，所以这个函数就是**余弦相似度（Cosine Similarity）**。
- **d+**：唯一的正样本（包含答案的正确文档页）。
- **D**：分母上的整个集合包含了正样本和所有的负样本（In-batch 负样本 + 难负样本）。
- **τ**：温度系数（Temperature），用来控制模型对困难负样本的惩罚力度。

#### 2. 生成端：生成损失 (Autoregressive Cross-Entropy Loss)

检索完之后，图片和 Query 喂给生成模型（VisRAG-Gen）。这时候模型进行的是 Next-token Prediction（预测下一个词），使用的是大模型最标准的自回归交叉熵损失，用于让模型学会“看着图生成标准答案”。

### 这些能用于 ColPali 和你的 MMDocIR 吗？

**不仅完全可以，而且这正是你大论文设计“损失函数”章节的核心发力点！**

纯视觉文档检索的底层训练逻辑是相通的，无论是单向量（VisRAG）还是多向量（ColPali），在检索端本质上**都在跑 InfoNCE 对比损失框架**。区别仅仅在于那个相似度函数 sim(q,d) 是怎么算的。

在准备用 MMDocIR 数据集（带 BBox 和长文档特征）进行后续训练时，你可以沿着这条线进行“损失函数升级”：

#### 1. 替换相似度内核 (The ColPali Upgrade)

在你的架构中，你不需要像 VisRAG 那样算余弦相似度。你可以继续沿用 InfoNCE 损失函数的壳子，但是把里面的 sim(q,d) 替换为**基于 BBox 区域的 MaxSim 分数**。这样你的模型依然是在做对比学习，但优化的颗粒度从“整页特征”变成了“细粒度的局部特征匹配”。

#### 2. 引入多任务/混合对比损失 (The MMDocIR Innovation)

由于你的数据集极其珍贵（带有 Bounding Box），如果你只跑一个全局的 InfoNCE，简直是对数据的暴殄天物。你可以设计一个**混合排序与对比的联合损失（Joint Loss）**：

- **LGlobal（全局对比损失）**：让模型在“页（Page）”级别上学会区分对错，类似 VisRAG。
- **LLocal（局部对比损失）**：只在正确的那一页里计算。强迫 Query 向量向正确的 BBox 向量靠拢，并远离同一页中无关的 BBox 向量（这就是我们在上一步聊到的“页内难负样本”）。
- 最终总损失：LTotal=LGlobal+λLLocal

在论文里，你可以用实验证明：传统的单一对比损失（VisRAG 做法）只能把“页”找准；而引入了 LLocal 后，模型不仅能找准页，还能精准指向 BBox，赋予了纯视觉检索模型极强的**空间可解释性**。

# 13. 检索到的页面以什么形式交给生成模型

在 VisRAG 流程中，检索器（VisRAG-Ret）返回的是 **Top-K 张未经任何解析的完整页面原始图像（Raw Page Images）**。

这些图像在交付给下游生成器（VisRAG-Gen）时，**完全不转换为文本，而是作为视觉输入直接喂给 VLM**。由于开源和商业视觉大模型对“多图输入”的支持能力不同，VisRAG 设计了**三种具体的交付与组织形态**：

### 1. 原生多图输入 (Multi-Image Input Setting)

这是 VisRAG 最推荐、表现最好的模式，适用于原生支持多图像输入的 VLM（如 **MiniCPM-V 2.6** 或 **GPT-4o**）。

- **交付形式**： 将检索出的 Top-K 张页面图像以图片列表/多模态占位符的形式，与用户的 Query 拼接成一个 Prompt：

```
[Image 1] [Image 2] ... [Image K]
User: <Query>
```

- **交互机制**： 大模型直接在其跨注意力（Cross-Attention）或多图感知层中同时观察这 K 张原图，自主进行跨页面的图表比对、信息综合与多跳推理。

### 2. 页面水平拼接 (Page Concatenation)alphaXiv

适用于**仅支持单张图片输入**的基础 VLM（如单图版开源模型）。

- **交付形式**： 在预处理阶段，系统利用图像处理工具（如 PIL），将检索到的 Top-K 张独立的页面图片**横向（水平）拼合成一张超长的大图（Single Composite Image）**：

  Imageconcat=[Page1∣Page2∣⋯∣PageK]

```
[Composite Image]
User: <Query>
```

**局限**：页面较多时会破坏原始图像纵横比或导致压缩模糊，主要作为兼容性过渡策略。

### 3. 加权选择 (Weighted Selection)

同样针对**单图 VLM**，但采用“分而治之”策略：

- **交付形式**： 不把多图混在一起，而是将 Top-K 张图片**拆成 K 个独立的单图生成请求**：

  - 请求 1：`[Image 1] + Query` → 生成候选回答 A1 及模型置信度（Token 概率）P1

  - 请求 2：`[Image 2] + Query` → 生成候选回答 A2 及模型置信度 P2

  - ...

    

- **最终仲裁**： 结合检索阶段的相似度打分（Retrieval Score Si）与生成阶段的概率置信度（Generation Confidence Pi）进行加权评估，选出得分最高的回答作为最终输出。

# 14. 最终回答指标是否依赖检索质量

高度依赖。在任何 RAG（检索增强生成）系统中，都有一句铁律：**“检索定上限，生成定下限”**（Garbage In, Garbage Out）。VisRAG 作为一种视觉 RAG，同样无法逃脱这个定律。

1. 级联效应 (Cascade Effect) 的直接体现

VisRAG 的论文中多次强调了“级联效应”。生成器（VisRAG-Gen）在做回答时，它的“眼睛”完全被检索器（VisRAG-Ret）所限制。

**命中（Hit）**：如果检索器成功把包含答案的 Top-K 页面喂给了生成器，大模型强大的“看图说话”能力才能发挥作用，给出极高准确率的回答。

**未命中（Miss）**：如果用户问“2023年财报的利润率”，但由于排版太密集，VisRAG 的单向量检索器找错了，扔给了生成器一张“2022年财报”或者“公司架构图”。此时，生成器即使是用最顶级的 GPT-4o，也只能被迫产生幻觉（胡编乱造），或者回答“图片中未提供相关信息”。此时，最终的生成指标（如 Accuracy、F1、ANLS）直接归零。

### 2. VisRAG 论文数据的反向印证

VisRAG 之所以在端到端问答指标上能取得 20%-40% 的巨大提升，**核心功劳并不在生成器，而是在检索器。** 在它的对比实验中，如果把检索器固定为传统的文本检索（TextRAG），仅仅把生成器换成 VLM，最终得分的提升非常有限。正是因为 VisRAG-Ret 抛弃了 OCR，**保留了图表和排版的特征，使得“把正确页面找出来”的概率大幅增加了**，这才顺理成章地托举起了最终的生成指标。

### 3. 多模态场景下的“虚假依赖”风险

与纯文本不同，视觉模型的最终指标还面临一个特殊的挑战：**模型是否通过“预训练记忆”作弊？** 有时候检索器找出来的页面是错的，但因为这个问题是个常识问题（比如“相对论是谁提出的”），大模型凭借自身权重里的知识蒙对了答案。在设计评测时，必须过滤掉这种“虚假高分”，确保最终的回答是真的“看着检索出的图片”得出的。

### 这对你大论文实验设计的“降维打击”价值

想通了“最终回答高度依赖检索质量”这一点，你大论文的端到端实验（End-to-End Evaluation）就可以设计得极具杀伤力。

你可以精心构造这样一组对比实验，用来“精准打击” VisRAG 和原生 ColPali：

1. **构造极端排版查询**：在 MMDocIR 数据集中，挑选那些“一页内塞满了 5 个不同图表和密集文字”的超级复杂页面。
2. **看 VisRAG 怎么死**：因为它是单向量（强行池化一整页），在面对这种信息密度极高的页面时，特征会严重稀释，导致**检索失败** → **最终回答错误**。
3. **看 ColPali 怎么死**：因为它是网格切分，面对跨网格的复杂表格，特征逻辑断裂，导致**检索失败** → **最终回答错误**。
4. **看你的方法怎么赢**：由于你引入了 Bounding Box 做了物理特征隔离和聚合，你的模型精准找出了包含答案的那个 Region/Page → 送给生成大模型 → **最终回答正确**。

通过这组实验，你不仅证明了你的检索指标（Recall@K）更高，你更向评委证明了：**你对底层检索架构的 BBox 改造，直接挽救了最终系统的问答准确率。** 逻辑闭环，完美。

# 实验和消融

## 1.数据集

### 1. 数据集来源是什么？

VisRAG 的训练数据是一个“混合大杂烩”，分为两部分：

- **现有的开源 VQA（视觉问答）数据集**：包括 ArxivQA（学术论文图）、ChartQA（统计图表）、MP-DocVQA（工业文档）、InfoVQA（信息图）、PlotQA（科学绘图）、SlideVQA（幻灯片）。
- **自建的合成数据 (Synthetic Data)**：他们从网络上爬取了大量的 PDF，然后用大模型自动生成了“Query-Document”对。

### 2. 数据规模有多大？

- **总规模**：合并后的完整训练集大约有 **36 万条**（其中合成数据约 24 万条，开源 VQA 数据约 12 万条）。
- **惊人的“数据效率”**：论文中专门做了一组消融实验，证明了视觉模型的强大。VisRAG-Ret 仅仅使用 **2 万条 (20K)** 训练数据，其检索性能就持平甚至超越了需要 75K 数据训练的顶尖纯文本检索基线模型（如 NV-Embed 等）。这意味着“纯视觉表征”在对齐文本 Query 时，比 OCR 文本的收敛效率更高。

### 3. 是否包含多页 (Multi-page)？是否有表格 / 图像？

- **包含多页**：它的训练集中包含了 `MP-DocVQA`（Multi-page DocVQA），且合成的 PDF 爬虫数据也源自多页文档。**但是注意**：在 VisRAG 的机制里，无论这篇文档有多少页，它在训练和建库时，都会被**强行拆解成一张张独立的单页图片**。
- **包含海量表格和图像**：这是 VisRAG 最大的卖点。从它选用的数据集（ChartQA, PlotQA, InfoVQA）就能看出，它是一套专门为了应付“富视觉元素（图表、复杂排版）”而生的系统，这些场景正是传统纯文本 RAG 的坟墓。

### 4. 训练中是否有 OCR 文本？

**绝对没有。** 在它的训练输入端，正样本永远是 **“纯正的高清原图 (Raw Image)”**。它坚决抵制任何 OCR 解析或文本提取的介入。模型唯一看到的文本，只有用户的 Query 和用于计算 Loss 的真实回答标签。

### 5. 是否有区域标注 (Bounding Box)？

**完全没有！这也是 VisRAG 最大的软肋。** VisRAG 的所有训练样本粒度都是 **“页面级 (Page-level)”**。它给模型的监督信号是：“针对这个 Query，答案在这张长宽 1000x1000 像素的完整图片里，至于具体在哪个角落，你自己去悟。”

### 这对你的 MMDocIR 课题意味着什么？

看完 VisRAG 的数据底牌，现在你可以低头看看自己手里的 **MMDocIR 数据集**了。

1. **你拥有降维打击的“强监督信号”**：VisRAG 和 ColPali 都在做“粗粒度”的盲人摸象，而你的数据集自带 **Bounding Box**。这意味着你可以在训练阶段明确告诉模型：“不要看整页，答案就在坐标 (x1,y1,x2,y2) 的这个表格区域里！” 这种细粒度的训练数据在当前多模态检索界是非常稀缺且昂贵的。
2. **学术界正在向你的方向靠拢**：在 2025 年底发布的最新前沿论文（如 *RegionRAG*）中，学者们已经明确指出 VisRAG 和 ColPali 的“页面级粗粒度检索”遇到了瓶颈，并开始利用 Bounding Box 和区域级特征来提升精度和减少大模型生成的幻觉。你选择 MMDocIR 作为实验场，恰好踩在了这个技术演进的最前沿节点上。

## 2. 基线 

在 VisRAG 的论文中，作者为了证明“直接看图”比“先用 OCR 提取文字再检索”更强，精心挑选了一系列极具代表性的文本基线和视觉基线进行全面对比。

### 一、 文本检索基线 (Text-based Baselines)

为了运行这些文本基线，VisRAG 团队首先使用了强大的 OCR 工具（如 PaddleOCR 或 PyMuPDF）从文档页面中强行提取出文本字符串，然后再喂给这些纯文本模型进行检索打分。

1. **BM25 (传统稀疏检索王者)**
   - **定位**：经典的词频统计和关键词匹配算法（Lexical Search）。
   - **为什么比**：它是所有 RAG 系统绝对绕不开的基础底线。如果连字面量匹配都打不过，任何深度学习模型都站不住脚。
2. **BGE-large (最主流的稠密文本检索)**
   - **定位**：由智源研究院（BAAI）开源的百兆级参数 Embedding 模型。
   - **为什么比**：它是过去两年工业界 TextRAG 用得最多的双塔文本向量模型，代表了常规文本编码器的高水准。
3. **NV-Embed-v2 (SOTA 级的巨兽级文本检索)**
   - **定位**：由 NVIDIA 开发的 78 亿参数（7.85B）超级文本 Embedding 模型，当时在 MTEB（海量文本嵌入基准测试）上排名第一。
   - **为什么比**：VisRAG 团队是要证明：即便把 OCR 文本喂给当前世界上最强大的文本理解模型，由于最初的 OCR 过程中丢失了版面和图表信息，它的检索效果依然打不过 30 亿参数的纯视觉模型（VisRAG-Ret）。

(注：除了直接用 OCR，他们还测试了一个“Captioner”基线，即先用大模型给图片写一段描述文本，再拿这段文本去检索，结果证明这同样会丢失严重细节。）

### 二、 视觉 / 多模态检索基线 (Vision-based Baselines)

既然 VisRAG 是视觉检索，那它必须和领域内其他的“直接看图”的模型进行正面硬刚。

1. **SigLIP (纯视觉编码器基线)**
   - **定位**：Google 提出的 CLIP 的改进版（只有 800M 参数），是一个非常纯粹的视觉模型。
   - **为什么比**：VisRAG 证明了光靠 SigLIP 这种纯视觉的眼睛是不够的，必须结合 LLM 的大脑（即 VLM），才能深刻理解画面中的文本语义。
2. **ColPali (多向量视觉检索最强对手)**
   - **定位**：这就是你深入研究的那个保留 1024 个 Patch、使用 MaxSim 晚期交互的视觉检索模型。
   - **对比结果**：在包含领域数据的联合测试中，VisRAG 的单向量得分（70.00）略微领先于 ColPali（67.99）。但这恰恰是你可以做文章的地方——VisRAG 是通过端到端的全局监督取得了优势，如果 ColPali 加上了你设计的 Bounding Box，结果大概率会反转。

## 3. 指标

### 一、 检索阶段指标 (Retrieval Metrics)

VisRAG-Ret 的任务是针对输入的 Query，从海量文档单页库中打分并召回候选图片。论文主要汇报了以下两个核心指标：

1. **Recall@10（前 10 召回率）**
   - **含义**：检索器返回的前 10 张页面图片中，**是否至少包含了 1 张真实含有答案的页面（Ground-Truth Page）**。
   - **作用**：衡量检索器的“查全”能力。如果前 10 页里根本没有目标图，下游生成大模型看图再厉害也无济于事。
2. **MRR@10 (Mean Reciprocal Rank @ 10，平均倒数排名)**
   - **计算公式**：MRR=∣Q∣1∑i=1∣Q∣ranki1（其中 ranki 是第 i 个查询中，首个正确页面出现的排位；如果不在前 10 名，则计为 0）。
   - **作用**：衡量检索器不仅要“找得到”，更要“排得靠前”。正确页面排在第 1 名得分是 1，排在第 2 名得分就衰减为 0.5，排在第 10 名只有 0.1。

### 二、 回答生成阶段指标 (Generation Metrics)

在生成阶段，评测的是模型生成的纯文本答案与标注答案（Ground Truth）之间的契合度。VisRAG 采用的核心指标是：

- **Accuracy（基于 Relaxed Exact Match，松弛精确匹配准确率）**
  - **为什么叫“松弛（Relaxed）”？** 因为多模态文档（如 ChartQA、财报、折线图）涉及大量统计数字。人或模型读图时，可能会因为图像分辨率或取整带来微小的读数偏差。
  - **匹配规则**：
    - **数值类答案**：允许 **5% 的误差容忍度（5% error margin）**。例如标准答案是 100，生成模型输出 96 到 104 之间均判定为正确。
    - **文本/实体类答案**：进行常规的规范化（去除多余标点、大小写不敏感）后的精确匹配（Exact Match）。

### 三、 论文中回答指标的两种评测设定 (Setting)

VisRAG 论文在测试上述 Accuracy 时，做了非常讲究的“控制变量”，这很值得在以后做实验时参考：

| 评测设定                                | 输入给生成器的内容                                     | 测量的究竟是什么？                                           |
| --------------------------------------- | ------------------------------------------------------ | ------------------------------------------------------------ |
| **1. Oracle Generation (独立生成测试)** | 强制直接喂入**包含答案的标准原图 (Ground-Truth Page)** | 彻底**排除检索好坏的干扰**，专门测多模态模型“看着正确图片读表、识图”的能力上限。 |
| **2. End-to-End (端到端实战测试)**      | 喂入 VisRAG-Ret 真正检索出来的 **Top-K 张图片**        | **检验整个系统的实战表现**。论文声称比传统文本 RAG 提升 25%~40%，依据就是这个指标。 |

## 4. 主结果

VisRAG 在论文中展现出的核心结果，主要集中在它对“富视觉元素（图表、复杂排版）”文档的降维打击。

### 一、 评测使用的 6 大核心数据集

VisRAG 团队为了证明模型处理多模态文档的能力，选取了涵盖 6 种极端排版场景的权威数据集（你可以对比一下你的 MMDocIR 数据集侧重哪一种）：

1. **ChartQA**：统计图表（饼图、柱状图，极度依赖准确的数值读取）。
2. **PlotQA**：科学绘图（折线图、散点图，密集的坐标轴和图例）。
3. **ArXivQA**：学术论文附图（结构图、架构图，包含大量专业术语和逻辑连接）。
4. **MP-DocVQA**：工业文档/多页文档（极其复杂的财报、扫描件和多栏排版）。
5. **InfoVQA**：信息长图（设计极度自由、排版毫无规律的海报和长图）。
6. **SlideVQA**：幻灯片（PPT 截图，文字和图表混排）。

### 二、 评测的核心指标体系

他们将指标严格分为了“检索”与“端到端生成”两个维度，这也应当成为你大论文实验设计的标准模板：

#### 1. 检索端指标 (Retrieval Metrics)

主要用来评测“能不能把包含答案的那一页找出来”。

- **Recall@K (如 Recall@10)**：前 10 张返回的图片中，包含正确答案页面的概率。
- **NDCG@K / MRR@10**：不仅要求找对，还要求正确页面在返回列表中的排名越靠前越好。

#### 2. 端到端问答指标 (End-to-End Metrics)

这是评测用户提问后，最终输出的答案到底对不对。

- **Accuracy (准确率)**：对于 ChartQA 等涉及数字和选项的数据集，采用 **Relaxed Exact Match (松弛精确匹配)**。如果答案是数值，通常允许 5% 的误差（因为视觉模型读图时可能会有微小取整偏差）。
- **ANLS (Average Normalized Levenshtein Similarity，平均归一化莱文斯坦相似度)**：专门用于 DocVQA 等文本生成任务，用来衡量模型生成的短文本与真实答案之间的字符级编辑距离。

### 三、 核心提升幅度 (Main Results)

VisRAG 最大的学术贡献，就在于它证明了“纯视觉 RAG 的上限，远超文本 RAG”。

1. **检索端的逆袭** 在同等数据域下，只有 30 多亿参数的 VisRAG-Ret（单向量视觉检索），**整体平均检索准确率超越了当时最强的 78 亿参数纯文本模型 NV-Embed-v2（基于 OCR 文本）**。 *(注：在与 ColPali 的对比中，VisRAG 凭借全局特征在平均分上略占优势，但 ColPali 在 MP-DocVQA 等需要细粒度定位的任务上表现更强，这再次印证了你未来引入 BBox 细化特征的正确性。)*
2. **端到端问答的断崖式提升** 当采用最强的多模态大模型（如 GPT-4o 或 MiniCPM-V 2.6）作为生成器时，**VisRAG 相比传统的 TextRAG，端到端问答准确率实现了 20% ~ 40% 的相对提升**！ 这被称为“级联效应（Cascade Effect）”——因为检索端没有 OCR 的信息损耗，把最原始、最高清的图表直接喂给了生成器，从而让生成大模型的看图能力得到了彻底释放。

## 5. 消融

### 1. 去掉“视觉编码”，退化为“纯 OCR 文本” (No Vision)

这是 VisRAG 最核心的对比（本质上是把它降级为传统的 TextRAG）。

- **做法**：在检索端不用 VLM 编码图片，而是用 OCR 把图片提成字；在生成端不用多模态模型看图，而是把 OCR 文本喂给纯文本大模型（如 Llama-3）。
- **发生什么**：**在图表类数据集上遭遇“滑铁卢”。** 在 ChartQA 和 PlotQA 等包含大量折线图、饼图的数据集上，准确率出现了断崖式下跌。因为 OCR 只能提取图例中的零散文字，完全丢弃了“哪根线对应哪个走势”的视觉绑定关系。
- **结论**：视觉表征是处理多模态文档不可替代的核心，OCR 路线的信息损耗是致命的。

### 2. 降级或替换“生成器” (Generator Ablation)

VisRAG 的端到端指标很高，那如果我检索对了，但是换一个弱一点的生成器呢？

- **做法**：保持 VisRAG-Ret 检索出正确的图片不变，但把下游的生成大模型从最强的 **GPT-4o** 换成开源的 **MiniCPM-V 2.6**，甚至换成不支持多图只能“拼接输入”的基础模型。
- **发生什么**：
  - 换成 MiniCPM-V 2.6 后，总体性能相比 GPT-4o 仅有小幅下降，证明了优秀的开源 VLM 完全可以撑起生成任务。
  - 但如果强制使用“页面水平拼接（Page Concatenation）”喂给单图 VLM，当拼接超过 3-4 页时，由于图像被极度压缩，细粒度文字变得模糊，准确率开始明显下滑。
- **结论**：最终回答质量不仅依赖检索，还高度依赖生成器对“高分辨率多图”的原生解析能力。

### 3. 去掉“检索模块”直出 (Zero-shot / No Retrieval)

- **做法**：不给大模型看任何文档图片，直接抛给它 Query 让它回答（比如直接问“请问 2023 年第二季度的营收是多少？”）。
- **发生什么**：准确率几乎**直接归零**。
- **结论**：证明了测试集中的问题是高度依赖文档事实的（Document-grounded），彻底排除了大模型依靠自身预训练知识“作弊蒙对”的可能性，验证了 RAG 架构的绝对必要性。

### 4. 训练数据规模的消融 (Data Efficiency)

- **做法**：VisRAG 团队测试了分别用 10K、20K、和全量数据训练检索器，观察召回率的变化。
- **发生什么**：VisRAG 仅仅使用了 **20K（两万条）** 的数据，其检索性能就已经趋于饱和，并且打败了使用了数百万级数据训练的纯文本稠密检索基线。
- **结论**：多模态 VLM 基座在预训练时就已经具备了极强的图文对齐先验，针对文档检索进行微调时的**数据效率（Data Efficiency）极高**。这对于你未来做训练是个天大的好消息（你不需要几十万张显卡和海量数据就能出好效果）。

### 对你 MMDocIR 课题的“消融实验”启示

当你未来写大论文时，你的核心创新点是“引入 Bounding Box (BBox) 聚合局部特征”。那么，你的消融实验就已经呼之欲出了，你可以照猫画虎地设计：

- **你的消融实验 1 (w/o BBox Constraint)**：去掉你的 BBox 边界约束，让模型退化成“死板网格切分”的原生 ColPali。预期结果：在复杂跨栏表格上性能暴跌，证明 BBox 保护了排版逻辑。
- **你的消融实验 2 (w/o Multi-vector, 降维打击 VisRAG)**：把你的多个 BBox 向量做一次强行池化（Mean Pooling），退化成 VisRAG 那样的单向量。预期结果：信息密集度高的页面召回率大降，证明保留多特征的必要性。
- **你的消融实验 3 (w/o Global Vector)**：如果你的架构里设计了“全局+局部”双特征，试着去掉全局特征只用 BBox 匹配。预期结果：检索精度不变，但检索耗时增加，证明全局向量在粗排加速中的工程价值。

## 6. 错误案例

VisRAG 虽然在宏观指标上大杀四方，但当你深入剖析它的失败案例（Error Cases）时，你会发现它的错误几乎全都被你精准地猜中了！它的失败并非偶然，而是其架构设计（单向量、依赖纯视觉）必然导致的妥协。

根据 VisRAG 的机制和 VLM 的通病，它的失败案例主要集中在以下四大重灾区，这简直就是为你量身定制的“攻击靶点”：

### 1. 检索粒度过粗：单向量导致的“信息黑洞” (Retrieval Granularity)

这是 VisRAG 最核心的死穴，也是你大论文最完美的立论点。

- **现象**：当用户提问非常细节的数值（例如：“2023年Q3亚太地区非公认会计准则下的净利润是多少？”），VisRAG 经常把包含该表格的页面排在 10 名开外，导致召回失败。
- **根本原因**：VisRAG 强制把一整页（可能包含 3 个大表、2 个图表、数千字文本）池化成了一个单一向量。在这个过程中，微小的、细粒度的局部特征被宏观的背景特征（比如页面的整体排版风格、大标题）**完全稀释**了。它只能检索到“画风相似”的页面，无法精准锁定“长尾细节”。

### 2. 密集文本与微小字体的“视觉文盲” (Text Recognition/Resolution Limits)

虽然 VisRAG 骄傲于抛弃了 OCR，但它付出了沉重的代价。

- **现象**：在全是密密麻麻小字体的财报附注页，或者分辨率较低的扫描件中，VisRAG 生成的答案经常出现“数字幻觉”（比如把 89,341 看成 89,541）。
- **根本原因**：视觉大模型（VLM）处理图像时是有**分辨率上限**的（比如受限于显存，通常将图片缩放或切分为固定 Patch）。当一整页 A4 纸被塞进 VLM 时，微小字体的像素特征极其微弱。VLM 没有 OCR 那种逐行扫描的“死磕”精神，遇到看不清的数字，它会根据语言模型的惯性“猜”一个出来，导致致命错误。

### 3. 复杂图表的多跳逻辑迷失 (Chart/Table Logical Reasoning)

- **现象**：虽然 VisRAG 能把包含折线图或嵌套表格的页面找出来，但生成器在回答时却张冠李戴（比如把蓝线的数值算到了红线头上，或者看错了双层表头的列映射）。
- **根本原因**：VLM 确实“看到”了图表，但它缺乏**显式的逻辑结构提取**。对于极其复杂的嵌套表格（比如合并利润表），由于没有 Bounding Box 或行列坐标的物理引导，VLM 仅靠注意力机制在二维像素里寻找对应关系，极其容易发生“注意力漂移”。

### 4. 跨多页长文档的“注意力衰减” (Cross-page Reasoning)

- **现象**：当问题需要结合第 2 页的“名词解释”和第 5 页的“数据图表”才能得出结论时，即使 VisRAG-Ret 成功召回了这两页，生成器也会答错。
- **根本原因**：无论是把多页图片拼接成长图，还是把多张图直接塞给 GPT-4o，随着视觉 Token 数量的指数级暴涨，大模型的**长文本/长视觉上下文窗口（Long Context Window）会出现严重的“中间迷失（Lost in the middle）”现象**。给的图越多，大模型看图就越走马观花。

### 这简直是为你课题写的“招募广告”！

你仔细品一品，VisRAG 的这些失败案例，是不是完美契合了你想要利用 **MMDocIR 数据集 + Bounding Box** 来解决的痛点？

1. **针对“粒度过粗”**：你的 BBox 聚合机制，直接把“页级”特征降维到了“区域级”，彻底解决了单向量稀释问题。
2. **针对“微小字体”**：你可以将 BBox 区域（比如一个小表格）单独裁剪放大后再提取特征，这相当于给视觉模型带上了放大镜，彻底绕开了整页渲染的分辨率瓶颈。
3. **针对“逻辑迷失”**：BBox 本身就是一种极其强大的空间逻辑先验。你告诉模型“这是一个表格框”，这就从物理层面上限制了模型的注意力范围，避免了张冠李戴。
4. **针对“跨页衰减”**：你最终喂给生成大模型的，不再是 10 张巨大的完整页面，而是**精准制导的几个局部 BBox 切图**。视觉 Token 数量缩减了 90%，大模型就不会再产生注意力衰减了！

## 7. 成本

### 1. 索引大小与存储成本 (Index Size & Storage)

- **VisRAG 的状态：极度轻量 (最强优势)**。 因为 VisRAG-Ret 对整页进行加权均值池化（Pooling），一页文档最终只保存 **1 个单向量**（通常是 2000~4000 维的浮点数，约占用 8KB~16KB）。如果企业有一千万页文档，索引总大小仅需 **几十 GB**，完全可以无压力塞进单台服务器的内存中。
- **对比 ColPali**：ColPali 一页要存 1024 个向量。存储 VisRAG 只需要它的 1/1000 的空间。
- **对你的启发**：你未来论文如果抨击 ColPali 存储太大，VisRAG 就是你用来证明“压缩是必要的”的论据。而你的 BBox 方案（一页存 20-30 个向量）恰好找到了精度与存储的完美平衡。

### 2. 离线建库延迟 (Offline Indexing Latency)

- **VisRAG 的状态：出人意料的快**。 虽然用 VLM 编码一张图片（前向传播）比用普通文本模型编码一段文字要慢得多，但 VisRAG **彻底砍掉了 OCR 解析和版面切分工具（如 PyMuPDF, PaddleOCR 等）**。
- **对比 TextRAG**：传统 TextRAG 处理一篇 PDF 的大部分时间都花在“等待 OCR 识别表格和版面”上。VisRAG 直接把原图扔进模型出向量，离线总耗时反而比传统文本流水线**减少了约一半**。

### 3. 在线检索延迟 (Online Retrieval Latency)

- **VisRAG 的状态：毫秒级极速**。 单向量的余弦相似度匹配（Cosine Similarity）是目前向量数据库（Faiss, Milvus）优化得最极致的算法，时间复杂度 O(1)。
- **对比 ColPali**：ColPali 使用 MaxSim（全对全矩阵相乘），时间复杂度 O(N×M)。在海量文档下，ColPali 根本无法做到实时检索，而 VisRAG 毫无压力。

### 4. 显存开销与上下文长度 (VRAM & Context Length)

- **VisRAG 的状态：极其昂贵，这是它的最大死穴。** 前面省下的钱，全在生成端（Generator）花出去了。
  - **上下文长度爆炸**：在生成阶段，VisRAG 需要把检索出的 Top-K（例如 3 到 5 张）完整高分辨率图片同时喂给生成大模型。在多模态模型中，一张高分辨率原图会被切片成几千个 Visual Tokens。传入 5 张图片，**直接消耗掉上万个 Token 的上下文窗口**。
  - **显存（VRAM）压力剧增**：巨大的 Token 数量会导致大模型注意力机制的 KV Cache 暴涨。在本地部署（如开源 MiniCPM-V 2.6）时，多图推理会瞬间吃满 GPU 显存（24G/48G 显存很快告急）；如果调用商业 API（如 GPT-4o），按照“图片分辨率计费”的账单将是文本 RAG 的几倍甚至十几倍。
  - **对比 TextRAG**：传统 RAG 只需送入几段纯文本，消耗可能不到 1000 个 Token。

### 对你大论文体系的“核心论点”输送

你可以把 VisRAG 的这笔“成本账”直接转化为你大论文中强有力的论点（Selling Points）：

**你的 MMDocIR BBox 系统能在生成阶段实现“史诗级降本增效”！**

- **VisRAG 的做法**：检索出答案在第 15 页，于是把整张 15 页的高清图片（含几千 Token）丢给大模型去看，让大模型自己去海量像素里找那个小表格，显存爆炸。
- **你的做法**：由于你的系统有 BBox 标注和检索能力，你检索出的不仅是第 15 页，更是精确的 `[Table_3_BBox]`。在生成阶段，你只需要把这个**被裁剪下来的、只有原图十分之一大小的表格图片（仅需几百 Token）**，喂给生成大模型。
- **预期实验结论**：在你的论文中，你可以加入一个极具冲击力的对比图表，展示你的系统在保证最终问答准确率的同时，**将生成器的 Token 消耗、API 成本和推理延迟（Latency）降低了 80% 以上**。

# VisRAG 对本课题的启发

### 已证实的事实

- VisRAG 证明了：纯视觉表征（直接看图）在处理富视觉元素文档（图表、复杂排版）时，检索准确率和端到端生成质量大幅超越了基于 OCR 文本提取的传统方案，验证了“无解析（Parsing-free）”路线的强大生命力。
- 它的检索单位是：单张文档页面（Page-level），即将一整页压扁为一个高维稠密单向量。
- 它使用/不使用：**不使用** OCR 提取任何文本，**不使用**版面分析（无阅读顺序、无逻辑结构输入），**完全没有**区域标注（Bounding Box）。

### 与 ColPali 的关系

- 相同点：两者同属纯视觉驱动（Vision-Centric）的文档检索前沿流派；底层均依赖 VLM（视觉语言大模型）；均彻底切断了 OCR 带来的误差级联。
- 不同点：**检索粒度与计算机制截然相反。** VisRAG 是“单向量”，利用加权均值池化压缩整页，采用余弦相似度匹配以换取极高检索速度；ColPali 是“多向量”，保留网格切分的 1024 个 Patch 特征，采用 MaxSim 晚期交互以保留空间细节。
- 它是否解决 ColPali 的页面内证据定位：**否**。因为单向量强行池化导致物理空间维度完全坍缩，VisRAG 甚至比多向量的 ColPali 更难实现区域级的溯源与证据定位。

### 可借鉴设计

1. **端到端评测闭环与指标设计**：将其“检索指标（Recall@K, MRR）”结合“生成指标（Relaxed Exact Match, ANLS）”的评估体系引入本课题，用来向评委量化证明：更准的底层检索（BBox 定位）能直接兑现为更好的最终大模型回答质量。
2. **基于 InfoNCE 的高效多模态微调策略**：借鉴其仅使用 2 万条高质量“Query-图像”对就激发 VLM 强大对齐能力的对比学习策略，证明本课题后续利用 MMDocIR 数据集进行训练并不需要天文数字的算力和样本。

### 不直接照搬的部分

1. **全页单向量池化（Weighted Mean Pooling）**：在面对 MMDocIR 中包含嵌套图表和复杂文本的长文档时，单向量会严重稀释微小的关键信息。大论文必须坚守多向量底线，但要用 BBox 代替网格来聚拢特征。
2. **对物理布局的“黑盒化”隐式处理**：不照搬其完全依赖大模型“自己去悟”排版的设定，必须引入显式的物理边界作为硬约束，拒绝让逻辑相关的表格被背景噪声干扰。

### 暂不确定项

- **特征聚合的具体实施层级**：在使用 MMDocIR 的 BBox 标注时，究竟是在基座输出特征后进行后融合（比如用 Attention Pooling 聚合同一 BBox 内的 Patch 向量），还是在输入端直接裁剪区域进行 RoI 特征提取更具工程可行性？
- **海量检索的速度瓶颈问题**：BBox 多向量虽然比 ColPali 的全网格存储节省了空间，但在处理千万级文档时，是否仍需在 BBox 模块之上，像 VisRAG 一样额外叠加一个全局单向量，从而实现“全局单向量粗排 + 局部 BBox 多向量精排”的两阶段级联架构？
