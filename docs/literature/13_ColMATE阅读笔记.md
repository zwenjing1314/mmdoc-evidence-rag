# 论文提到的限制与解决组件

现存的三个主要限制

**限制一：视觉token在预训练时缺乏显式优化**。现有的方法通常使用预训练的视觉语言模型（如PaliGemma）来获取视觉表示。然而，这些模型在预训练期间并没有显式地优化输出的视觉token，因为它们的自回归损失仅应用于后续的文本token。这种做法限制了模型在进行细粒度视觉检索时的有效性。

**限制二：严重依赖监督微调**。现有的模型严重依赖带有标注的查询-文档对（query-document pairs）进行监督微调，以实现跨模态对齐。这种依赖性限制了模型在缺乏此类标注数据的领域中的适用性。

**限制三：传统的后期交互机制不适用于视觉上下文**。现有方法采用了最初为文本检索设计的后期交互机制（如MaxSim），这些机制假设查询和文档的token之间存在一对一的对应关系。但在视觉环境中，这种假设不成立，因为基于图像块（patch）的token化可能会将一个单词碎片化到多个图像块中，或者将多个单词合并到单个图像块中。这会在训练期间的相似度计算中引入噪声，并最终降低检索性能。   

提出的三个互补组件

为了解决上述限制，COLMATE模型在预训练、微调和后期交互阶段引入了以下三个互补组件：  

**组件一：掩码OCR语言建模（Masked OCR Language Modeling, 简称MOLM）**。该组件用于预训练阶段，通过预测被掩码的OCR token，显式地优化了视觉token的表示。这直接解决了现有视觉语言模型在预训练时未能充分优化视觉特征的问题，从而获得了更丰富的视觉-文本表示。 

**组件二：自监督掩码对比学习（Self-supervised Masked Contrastive Learning, 简称MaskedCL）**。该组件能够在没有标注的查询-文档对的情况下，实现掩码文本和文档特征之间的跨模态对齐。这使得模型能够在缺乏人工标注数据的场景中进行有效的自我监督学习和泛化。 

**组件三：改进的后期交互机制（TopKSim）**。TopKSim通过在训练期间平均前K个（top-K）相似度得分，而不是仅仅依赖单一的最大得分。这一机制减轻了视觉文档中由于基于图像块的token化所引发的训练噪声，减少了对单个图像块的过度依赖，从而使得检索和匹配过程更加鲁棒。

# 1. 论文解决的具体问题

COLMATE总体上仍然是基于类似ColPali的框架构建的。论文明确指出，COLMATE是建立在ColPali模型的基础之上的，选择它的主要原因是ColPali具有更快的运行速度。COLMATE与ColPali一样，也是从`paligemma-448-base`检查点初始化训练的。COLMATE的核心贡献在于通过引入三个新组件，弥补了现有框架在多模态表示学习和文档检索之间的差距。

文解决的具体问题，主要是为了克服现有多模态文档检索模型（尤其是直接移植纯文本检索技术的模型）在处理富含图表、表格等视觉和空间信息的文档时面临的三大挑战：   

- **问题一：预训练阶段视觉特征表示未得到充分优化。** 现有的模型通常依赖PaliGemma等预训练的视觉语言模型（VLM）来获取视觉表示。然而，这些VLM在预训练时，其自回归损失通常只应用于后续的文本token，并没有显式地优化最后输出的视觉token。这导致模型在进行细粒度的视觉检索时效果受限。正如您提供的图片(a)部分所示，COLMATE通过引入掩码OCR语言建模（Masked OCR LM），要求模型根据视觉上下文预测被掩码的OCR token，从而显式地优化了视觉token的表示。   
- **问题二：对高质量监督数据的严重依赖。** 现有多模态检索模型严重依赖带有标注的查询-文档对（query-document pairs）来进行监督微调以实现跨模态对齐。这种做法极大地限制了模型在缺乏此类标注数据的专业领域中的适用性和泛化能力。正如图片(b)部分所示，为了解决这个问题，论文提出了掩码对比学习（Masked Contrastive Learning），能够在没有查询-文档对的情况下，实现掩码文本与文档特征之间的自监督跨模态对齐。   
- **问题三：传统后期交互机制在视觉上下文中的不匹配（训练噪声）。** 现有的方法采用了最初为文本检索设计的MaxSim后期交互机制。MaxSim假设查询token和文档token之间存在完美的“一对一”对应关系。但在视觉文档中，由于采用了基于图像块（patch）的token化方式，一个单词可能会被碎片化地分割到多个图像块中，或者多个单词被合并到了同一个图像块中。这种假设的破裂会在训练过程中的相似度计算里引入大量噪声，最终降低检索性能。正如图片(c)部分所示，论文通过引入TopKSim机制来改进后期交互，通过在训练期间对前K个相似度得分求平均值，有效地减少了由这种基于图像块的token化所带来的噪声



# 2.模型的输入和输出

### 1. 实际检索（推理）阶段 (Inference/Retrieval Stage)

这是模型最终在实际应用中的工作方式（参考图片(c)的右侧流程）。

- **输入 (Inputs)：**
  - **查询端 (Query)：** 用户的文本形式查询请求。   
  - **文档端 (Image/Document)：** 视觉文档的图像（例如，将PDF的一页渲染成的图像文件）。   
- **输出 (Outputs)：**
  - **中间输出（特征嵌入）：** 模型内部会通过视觉编码器（Vision Encoder）和大型语言模型（LLM）层，分别输出文本查询和文档图像的上下文token级特征向量（Embeddings）。   
  - **最终输出（相似度得分 - Score）：** 系统最终输出一个标量得分，表示该文本查询与该文档图像的匹配程度。在推理时，模型会使用MaxSim机制计算这些特征向量之间的相似度，从而对候选文档进行排名。   

### 2. 训练阶段 (Training Stage) 的输入输出

在论文提出的三个不同组件的训练过程中，输入和输出有特定的设计以优化模型：

- **针对组件一：掩码OCR语言建模 (MOLM) - 预训练阶段**
  - **输入：** 完整的文档图像。   
  - **输出：** 模型输出池化后的视觉token嵌入，并利用这些嵌入来输出**预测概率**，即预测出那些被刻意掩码（Masked）掉的OCR真实词汇是什么。   
- **针对组件二：掩码对比学习 (MaskedCL) - 自监督微调阶段**
  - **输入：** 两部分内容。一是带有随机掩码的文档提取文本（作为“伪查询”）；二是叠加了随机白色掩码块的对应文档图像。   
  - **输出：** 掩码文本特征和掩码视觉特征之间的**对比学习相似度得分**，模型通过最大化正样本对的得分并最小化负样本对的得分来进行跨模态对齐。   
- **针对组件三：TopKSim - 监督微调阶段（替代传统MaxSim）**
  - **输入：** 编码后的查询token向量集合和文档图像token向量集合。   
  - **输出：** 一个经过平均处理的**相似度得分 (Score)**。模型不再仅仅输出单个最大相似度（MaxSim），而是找出每个查询token对应的前K个（top-K）最大点积相似度，然后输出它们的平均值作为该查询token的得分汇总，最终相加得到总分，以此来计算训练损失。

# 3.查询与页面编码

根据论文内容，查询和页面的编码处理以及掩码OCR语言建模（MOLM）的具体实现细节如下：

### 查询和页面的编码处理

COLMATE模型是建立在ColPali架构基础之上的，并初始化使用了PaliGemma模型的预训练权重。模型包含视觉编码器（Vision Encoder）和大型语言模型（LLM）层。   

- **页面（文档图像）编码：** 给定一个输入的文档图像，模型通过其架构（最终从LLM的输出中）提取出上下文化的视觉token嵌入向量（contextualized visual token embeddings）。这些文档特征被表示为一个向量集合 $d = \{d_1, d_2, ..., d_m\} \subset \mathbb{R}^d$（或用 $V = \{v_1, v_2, ..., v_N\} \subseteq \mathbb{R}^d$ 表示视觉token）。   
- **查询（文本）编码：** 文本查询被编码为一个特征向量集合，表示为 $q = \{q_1, q_2, ..., q_n\} \subset \mathbb{R}^d$。   

在获得这些向量集合后，模型使用后期交互机制（训练时使用TopKSim，推理时使用MaxSim）来计算查询token和文档token之间的点积（dot product）相似度得分。   

### 掩码OCR语言建模 (MOLM) 的具体实现细节

MOLM是一种新颖的预训练目标，旨在通过直接优化视觉token嵌入来丰富视觉表示。其具体实现分为以下几个步骤和实验设置：   

**1. 提取视觉特征与空间对齐** 首先，从LLM的输出中获取输入文档图像的上下文化视觉token嵌入 $V = \{v_1, v_2, ..., v_N\} \subseteq \mathbb{R}^d$。假设文档中有一个OCR单词token $w_j$ 及其对应的边界框（bounding box）。模型会找出在空间上与该单词边界框重叠的所有视觉token的索引集合，记为 $B_j \subseteq \{1, ..., N\}$。   

**2. 随机掩码 (Masking)** 模型会随机选择文档中 30% 的OCR token进行掩码操作，形成一个掩码集合 $\mathcal{M} \subset \{w_j\}$。   

**3. 特征池化 (Pooling)** 对于被掩码集合 $\mathcal{M}$ 中的每一个单词 $w_j$，模型会利用之前找到的重叠视觉token索引集合 $B_j$，计算这些视觉token的池化（平均）表示： $\overline{v}_j = \frac{1}{\vert{}B_j\vert{}} \sum_{i \in B_j} v_i$。   

**4. 预测与损失计算 (Prediction and Loss)** 使用池化后的视觉嵌入向量 $\overline{v}_j$，训练模型通过掩码语言建模目标来预测那些被掩码的真实OCR token。损失函数定义为： $\mathcal{L}_{MOLM} = - \sum_{w_j \in \mathcal{M}} \log p(w_j \vert{} \overline{v}_j, \theta)$。 这里的 $p(w_j \vert{} \overline{v}_j, \theta)$ 表示具有参数 $\theta$ 的模型根据视觉上下文预测出对应token $w_j$ 的概率。   

**5. 训练参数设置**

- **数据集：** MOLM组件的训练使用了来自 `pdfa-eng-wds` 数据集的400万（4M）份数字PDF文档页面，这些页面被渲染成96 dpi的图像。   
- **超参数：** 训练进行了 1 个epoch，学习率（learning rate）设置为 3e-5，批处理大小（batch size）为 64，优化器使用了 Adam。

# 4. TopKSiM

TopKSim与传统的MaxSim在实现机制和适用场景上有着明确的区别。以下是具体的实现细节与特点对比：   

### TopKSim 的具体实现

在给定编码后的查询token集合 q={q1,q2,...,qn} 和文档图像token集合 d={d1,d2,...,dm} 的情况下，TopKSim的具体计算过程如下：   

1. **计算点积：** 首先计算第 i 个查询token与第 j 个文档token之间的点积相似度，记为 ⟨qi∣dj⟩。   
2. **筛选前K个最大值：** 对于每一个固定的查询token qi，找出文档中与之点积得分最大的前 K 个文档token的索引集合，记为 Ii。   
3. **求平均与累加：** 计算这 K 个最大相似度得分的平均值，然后将查询中所有 n 个token的平均得分累加，得到最终的总分。   

其数学公式表示为：

Score(q,d)=i=1∑nK1j∈Ii∑⟨qi∣dj⟩

论文在初步实验中对比了 K∈{3,5,10}，最终发现在训练时设置 K=5 能够提供最佳的性能。值得注意的是，TopKSim**仅在模型训练期间**使用，在实际推理（Inference）阶段，模型会恢复使用MaxSim。   

### 传统 MaxSim 的特点

- **设计初衷与假设：** MaxSim最初是为纯文本检索模型（如ColBERT）设计的后期交互机制。它依赖于一个核心假设：查询token和文档token之间存在“一对一”的对应关系。   

- **文本场景优势：** 在处理纯文本时，token通常能够与有意义的语义单元（如单词）良好对齐，因此选取单一的最高相似度得分非常有效。   

- **视觉场景劣势：** 在视觉环境中，这种“一对一”的假设被打破。因为视觉文档使用基于图像块（patch）的token化方式，一个单词可能会被分割到多个图像块中，或者多个单词被合并到一个图像块中（这取决于图像块大小和字体渲染等因素）。如果直接在训练时应用MaxSim，这种碎片化会在相似度计算中引入明显的噪声，并降低检索性能。   

- **推理阶段表现：** 尽管在训练视觉模型时会引入噪声，但MaxSim在最终的推理阶段表现出了卓越的经验性能（superior empirical performance）。   

  

### TopKSim 的特点

- **缓解碎片化问题：** 通过计算前 K 个得分的平均值，而不是仅仅依赖单一的最大值，TopKSim有效适应了视觉token可能跨越多个图像块的现实情况。   
- **正则化作用：** 它起到了正则化器（regularizer）的作用，减轻了模型对单个图像块特征的过度依赖。   
- **降低训练噪声：** 该机制有效减少了因图像块token化在视觉文档中引发的训练噪声。   
- **提升鲁棒性与泛化能力：** 采用TopKSim使得查询-图像对的检索和匹配变得更加鲁棒。实验表明，它在未见过的领域（out-of-domain）基准测试中（如ViDoRe V2）实现了更好的泛化性能。
