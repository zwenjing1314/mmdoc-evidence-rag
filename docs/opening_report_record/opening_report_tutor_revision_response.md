# 导师意见对应修改建议

## 一、导师意见理解

导师给了两处意见：

```text
1. 不足不要写。
2. “研究方法”部分太像社科写法，自科需要写具体算法。
```

这两个意见都很关键。

原来的标题是：

```text
四、研究方法、创新和不足
```

建议改成：

```text
四、研究方法与创新点
```

或者：

```text
四、研究方法、技术路线与创新点
```

更推荐第二个，因为你的论文偏工程算法实现，写“技术路线”会更自然。

## 二、第一处修改：不要写“不足”

原来这一节中有：

```text
（四）预期不足与风险控制
```

导师说“不足不要写”，所以建议不要再出现“不足”两个字。

可以改成：

```text
（五）研究可行性与风险控制
```

或者：

```text
（五）实施风险与解决措施
```

更推荐：

```text
（五）研究可行性与风险控制
```

因为“可行性”是正向表述，“风险控制”是开题报告里可以写的，不会显得你主动暴露论文缺陷。

原来的内容也不要写成：

```text
本文存在以下不足……
```

应该写成：

```text
为保证研究顺利开展，本文从数据、模型、计算成本和评价可靠性等方面进行风险控制。
```

## 三、第二处修改：研究方法要改成具体算法

你原来的写法是：

```text
1. 文献分析法
2. 系统建模法
3. 对比实验法
4. 消融实验法
5. 案例分析法
```

这个确实偏社科论文。自然科学/工程类论文应该写：

```text
具体使用什么算法、什么模型、什么流程、什么评价方法。
```

所以建议把：

```text
四、研究方法、创新和不足
（一）研究方法
```

整体替换为下面这个版本。

## 四、可直接替换版本：研究方法

```text
四、研究方法、技术路线与创新点

（一）研究方法

本文围绕多模态长文档中的证据检索、证据定位与可信生成问题，采用“文档解析—证据节点构建—多阶段检索—证据融合重排序—证据约束生成—支持性验证”的技术路线，具体研究方法如下。

1. 多粒度证据节点构建方法。针对 PDF 长文档中页面多、表格多、证据位置分散的问题，本文首先使用文档解析工具对 PDF 进行逐页解析，抽取页面文本、文本块、表格块、页码、阅读顺序和版面坐标等信息。在此基础上，将页面、段落、表格块、表格行和图表区域统一建模为 evidence node。每个证据节点包含 node_id、doc_id、page_id、node_type、bbox、text、reading_order、source 和 metadata 等字段。对于中文年报中的财务表格，本文进一步根据营业收入、归属于上市公司股东的净利润、经营活动产生的现金流量净额、研发投入、资产总额等关键财务指标，构建表格行级证据节点，以提高数值型问题的证据定位能力。

2. 页面级粗召回算法。针对长文档页数多、直接在全部区域节点上检索成本较高的问题，本文首先在页面级进行候选页面召回。页面级检索采用 BM25、TF-IDF/Dense fallback 和向量检索等方法，将用户问题与页面文本表示进行相似度计算，得到 Top-k 候选页面。BM25 用作关键词检索 baseline，Dense 检索用于建模问题与页面之间的语义相关性。后续实验中将进一步引入 BGE-M3 等中文或多语种 embedding 模型，提高页面级语义召回能力。

3. 区域级细粒度证据检索算法。在页面级粗召回的基础上，本文仅在候选页面内部进行区域级检索，从而缩小检索空间。区域级候选包括 paragraph、table_block、table_row 等 evidence node。系统计算问题与候选节点之间的文本相似度或向量相似度，并结合页面级召回得分、节点类型、阅读顺序和财务关键词匹配信号进行排序。该方法的核心思想是先通过页面级检索降低长文档搜索空间，再通过区域级检索定位具体证据片段。

4. 多粒度排序融合方法。为融合页面级检索结果和区域级检索结果，本文采用 Reciprocal Rank Fusion（RRF）或加权融合方法计算最终证据得分。页面级得分用于表示该页与问题的整体相关性，区域级得分用于表示具体证据节点与问题的局部相关性。通过融合两类得分，系统既能保留页面级上下文先验，又能提高细粒度证据定位能力。

5. 证据增强生成方法。本文将检索得到的证据节点组织为 evidence cards，每张 evidence card 包含页码、节点类型、证据文本、区域坐标、检索得分和来源文档等信息。生成阶段要求模型仅基于 evidence cards 中的证据生成回答，并输出对应引用信息。对于数值型问题，生成输入中保留指标名称、数值、单位和证据页，以减少无依据生成和单位错误。

6. 答案支持性验证方法。针对文档 RAG 中可能出现的证据不足、引用错误和答案幻觉问题，本文设计答案支持性验证流程。对于财务数值问题，采用规则匹配和数值一致性校验，判断生成答案中的数值、单位和指标名称是否能在证据节点中找到支持；对于文本型问题，结合证据覆盖度、检索置信度和模型判断结果评估答案是否被证据支持。当证据不足或答案无法被证据支持时，系统执行二次检索或拒答。

7. 实验评价方法。本文通过对比实验、消融实验和错误分析验证所提方法有效性。检索阶段采用 Page Recall@k、MRR、nDCG@k 和 Region Hit@k 等指标评价页面召回和区域证据定位效果；生成阶段采用答案准确率、数值准确率、证据支持率、Unsupported Answer Rate 和拒答相关指标评价生成可信性；同时记录平均检索延迟、输入 token 数和候选页面数量等工程指标，分析方法的效率和可用性。
```

## 五、为什么这个版本更符合导师要求

这个版本不再写：

```text
文献分析法
系统建模法
案例分析法
```

而是直接写：

```text
证据节点构建方法
页面级粗召回算法
区域级证据检索算法
排序融合方法
证据增强生成方法
答案支持性验证方法
实验评价方法
```

这样更像自然科学和工程类论文。

导师看起来会觉得你不是在泛泛谈研究方法，而是已经知道：

1. 数据怎么表示；
2. 检索怎么算；
3. 排序怎么融合；
4. 生成怎么约束；
5. 可信性怎么验证；
6. 实验怎么评价。

## 六、原来的“预期不足与风险控制”怎么改

原来的标题：

```text
（四）预期不足与风险控制
```

建议改成：

```text
（五）研究可行性与风险控制
```

内容可以替换成下面这个版本。

```text
（五）研究可行性与风险控制

本文已完成中文年度报告小规模实验闭环，初步验证了数据解析、证据节点构建、页面级检索和区域级证据定位流程的可行性。后续研究将在该基础上逐步扩展公开数据集、多模态检索模型和可信生成模块。为保证研究顺利完成，本文从以下几个方面进行风险控制。

1. 数据处理方面。多模态长文档解析质量会影响后续检索和生成效果。本文优先使用 PyMuPDF、Docling、PaddleOCR 等成熟工具进行文档解析，并保留页面文本、区域坐标、节点类型和来源信息。对于解析失败或表格结构不完整的样本，将记录错误类型，并在实验分析中区分解析错误和检索错误。

2. 模型实现方面。本文不从零训练大规模多模态基础模型，而是采用 BM25、TF-IDF、BGE-M3、ColBERT 类模型和现有视觉文档检索模型作为基础组件，重点研究多粒度证据组织、页面—区域协同检索和证据支持性验证机制。这样可以降低模型训练成本，提高研究可实施性。

3. 实验规模方面。本文采用“公开数据集验证 + 中文年报小规模应用验证”的实验设计。公开数据集用于保证实验可复现性，中文年报数据用于体现中文复杂文档场景价值。若时间有限，将优先保证主检索实验、消融实验和可信验证实验完整完成，再扩展更多数据类型。

4. 可信性评价方面。由于单纯依赖 LLM-as-judge 可能存在不稳定性，本文将结合规则校验、数值一致性校验、证据覆盖度、检索置信度和人工抽样复核进行综合判断，降低可信性评价偏差。

5. 工程复现方面。本文将统一管理数据处理脚本、实验配置、运行日志、评价结果和案例分析材料，保证实验流程可复现，便于后续论文撰写和答辩展示。
```
