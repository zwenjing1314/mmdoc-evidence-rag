# 开题现场模拟问答记录

本文档用于准备开题答辩现场可能被老师追问的问题。回答尽量采用现场口语化表达，重点说明“论文是否可行、创新点在哪里、用了哪些技术和模型、已有工作是否足够支撑后续毕业论文”。

## 一、毕业论文可行性相关问题

### Q1：你的题目听起来比较大，硕士论文时间内能完成吗？

**建议回答：**

老师，这个题目确实涉及多模态长文档和 RAG，但我不会从零训练多模态基础模型，也不会把 OCR、表格识别、图表识别都作为主创新点。我的研究边界是：在已有文档解析工具、检索模型和大语言模型基础上，重点研究长文档中的证据组织、证据检索、证据定位和可信验证。

目前我已经完成了中文年报的第一阶段检索实验，包括 20 份年报 PDF、5327 个页面、99304 个细粒度证据节点和 160 条人工修订问答样本，并实现了 BM25-page、Dense-page 和 Page→Region 三类 baseline。因此后续不是从零开始，而是在已有数据处理和检索实验基础上逐步扩展到强模型、生成验证和公开数据集，整体工作量是可控的。

### Q2：你现在做的工作能支撑研究生毕业论文吗？

**建议回答：**

我认为可以支撑，但需要按阶段推进。当前已经完成的是第一阶段检索实验，主要验证“页面级粗召回—区域级细定位”的可行性。后续论文工作还会继续扩展四部分：

1. 引入 BGE-M3、BGE-reranker、LayoutLMv3、ColPali 等模型做对比和消融；
2. 扩展到 MMDocIR、LongDocURL 或 MMLongBench-Doc 等公开数据集；
3. 补充证据增强生成、可信验证和拒答实验；
4. 做错误分析、效率分析和案例分析。

这样论文会覆盖数据构建、文档解析、证据节点建模、检索、重排序、生成、验证和评估，工作量能够支撑一篇硕士论文。

### Q3：为什么不直接做一个完整的大模型问答系统？

**建议回答：**

如果直接做完整系统，容易变成工程堆叠，难以分析每个模块是否真正有效。我的思路是先做可复现的 baseline，再逐步加入证据节点、页面-区域协同检索、多模态融合、重排序和可信验证。这样每一步都有对比实验和消融实验，可以明确说明改进来自哪里，也更符合论文研究要求。

## 二、创新点相关问题

### Q4：你的创新点是什么？和普通 RAG 有什么区别？

**建议回答：**

普通 RAG 通常把 PDF 转成纯文本，再按固定长度切块做向量检索。我的工作重点不是简单切文本，而是把长文档解析为页面、段落、表格块、表格行、图表区域等多粒度证据节点，并保留页码、区域坐标、节点类型和来源信息。

主要创新体现在三个方面：

1. 构建面向检索、定位和验证的多粒度证据节点表示；
2. 设计页面级粗召回和区域级细定位相结合的检索方法；
3. 在生成后增加证据支持性验证和拒答机制，使系统不只是回答问题，还要判断答案是否有证据支持。

### Q5：你说的 evidence node 有什么研究价值？

**建议回答：**

evidence node 的价值在于把长文档中的内容从普通文本片段变成可检索、可定位、可引用和可验证的证据单元。每个节点不仅有文本，还包含页码、节点类型、区域坐标、来源文档等信息。

这样做可以解决两个问题：一是检索结果不再只是模糊的一段文本，而能定位到具体页面和区域；二是生成答案后可以反查证据节点，判断答案是否被证据支持。这也是后续可信生成和拒答机制的基础。

### Q6：Page→Region 方法的创新在哪里？

**建议回答：**

长文档页面很多，如果直接在所有段落和表格行上检索，搜索空间大、效率低，而且容易引入噪声。Page→Region 的思路是先在页面级召回候选页面，再在候选页面内部检索具体证据节点。

这个方法的价值是同时兼顾效率和定位精度：页面级召回缩小搜索范围，区域级检索提高证据定位粒度。当前中文年报实验已经初步验证，Page→Region 能够返回细粒度证据节点，Region Hit@5 达到 0.2000，说明这个方向是可行的。

### Q7：拒答机制算创新吗？

**建议回答：**

拒答机制本身不是全新的概念，但在多模态长文档 RAG 中非常重要。本文不是单独提出一个拒答模型，而是把拒答机制放在“证据检索—证据组织—生成—验证—决策”的闭环中。

当检索证据不足、证据冲突、数值单位不一致，或者生成答案无法被证据节点支持时，系统不直接强行回答，而是执行二次检索或拒答。这能够降低无依据生成和错误引用风险，是可信生成部分的重要组成。

## 三、技术与模型相关问题

### Q8：你的论文具体会用到哪些模型和技术？

**建议回答：**

我的技术路线分为几个模块：

1. 文档解析：PyMuPDF、Docling、PaddleOCR，用于提取页面文本、文本块、表格区域、图像区域和坐标；
2. 文本检索：BM25、TF-IDF、BGE-M3，用于页面级和节点级语义检索；
3. 版面建模：LayoutLMv3、LiLT，用于利用文本、bbox 和版面结构信息；
4. 视觉检索：ColPali、ColQwen 或 CLIP/SigLIP，用于页面图像或区域图像检索；
5. 重排序：RRF、BGE-reranker 或 Cross-Encoder，用于融合多路检索结果；
6. 生成与验证：Qwen、DeepSeek、GLM 或其他大语言模型，结合规则校验和 LLM verifier 做答案支持性判断。

### Q9：你现在用的是 OCR 吗？图片里的文字能识别吗？

**建议回答：**

当前中文年报实验主要处理原生 PDF，使用 PyMuPDF 从 PDF 文本层中抽取页面文本、文本块和位置信息，所以它不是严格意义上的 OCR。对于扫描版 PDF 或图片里的文字，PyMuPDF 不能直接识别，需要接入 PaddleOCR、Docling OCR 或 PaddleOCR-VL。

后续系统会区分两类输入：原生 PDF 用 PyMuPDF 抽取文本层；扫描件或图片型 PDF 使用 OCR 模型识别文字和坐标，然后统一转成 evidence node。

### Q10：table_block 和 table_row 是真正的表格结构吗？

**建议回答：**

当前阶段的 table_block 和 table_row 更准确地说是“表格相关文本证据节点”，还不是完整的二维结构化表格。

table_block 是疑似表格区域的文本块，table_row 是从财务指标附近抽取出的行级证据，例如营业收入、归母净利润、经营活动现金流量净额等。它们在 parquet 中主要以文本、页码、节点类型、坐标和 metadata 形式存储。

后续如果进一步做表格结构识别，会把表格解析成行列标题、单元格和值，再构建 table_cell 或结构化 table_row 节点。

### Q11：折线图、柱状图这类图表怎么处理？文字抽不出来怎么办？

**建议回答：**

这个问题确实是当前阶段的边界。现在项目主要处理可抽取的文本、表格文本和页面级上下文，对于折线图、柱状图这种视觉信息，还没有完整做图表理解。

后续可以分两步扩展：第一步，把图表区域作为 chart_region 节点保存，记录图表区域坐标、图表标题、图注、周围文本和 image_path；第二步，引入视觉语言模型或图表解析模型，对图表生成结构化描述或数据表。这样可以把图表信息也纳入证据检索和生成过程。

### Q12：evidence cards 是什么？

**建议回答：**

evidence cards 可以理解为传给生成模型的结构化证据卡片。它不是一个现成模型，而是系统内部设计的一种证据组织格式。

每张 evidence card 主要包含来源文档、页码、证据节点编号、节点类型、证据文本、区域坐标、检索得分、单位信息等。生成模型不是直接面对一堆散乱文本，而是基于这些结构化证据卡片回答问题，并输出引用信息。这样便于后续检查答案是否真正被证据支持。

## 四、实验设计相关问题

### Q13：你现在的实验完成到什么程度？

**建议回答：**

当前完成的是中文年报的第一阶段检索实验。具体包括：

1. 20 份中文年报 PDF；
2. 5327 个页面；
3. 99304 个 paragraph、table_block、table_row 级证据节点；
4. 160 条人工修订问答样本；
5. BM25-page、Dense-page、Page→Region 三类检索 baseline；
6. Page Recall@k、MRR、nDCG@k、Region Hit@k 等指标评价。

还没有完成的是强模型检索、视觉检索、证据增强生成、可信验证和拒答实验，这些会作为后续论文主要工作继续推进。

### Q14：为什么先做中文年报，不先做公开数据集？

**建议回答：**

中文年报更贴近真实中文行业文档场景，而且包含大量财务表格、数值、单位、风险文本和跨页证据，适合验证证据定位和可信生成问题。开题前先用中文年报完成小规模可控实验，可以快速验证技术路线。

后续我会继续接入 MMDocIR、LongDocURL 或 MMLongBench-Doc 等公开数据集，用公开基准验证方法的泛化能力。也就是说，中文年报用于中文应用验证，公开数据集用于标准化对比实验。

### Q15：你的评价指标有哪些？

**建议回答：**

检索阶段主要使用 Page Recall@k、MRR、nDCG@k 和 Region Hit@k，分别评价页面召回、排序质量和区域级证据命中情况。

生成阶段会使用 EM、F1、ANLS、Numerical Accuracy 等答案指标，同时增加 Correct Answer with Correct Evidence Rate，也就是答案正确且证据正确的比例。

可信验证和拒答阶段会使用 Unsupported Answer Rate、Abstention Precision/Recall/F1、False Refusal Rate 和 False Answer Rate 等指标。

### Q16：你现在的 Region Hit@5 只有 0.2000，会不会太低？

**建议回答：**

这个结果是第一阶段 baseline，不是最终模型效果。当前 Page→Region 主要基于基础文本检索和规则节点切分，还没有引入 BGE-M3、BGE-reranker、LayoutLMv3、ColPali 等强模型，也没有做表格结构识别和视觉检索。

所以这个结果的意义不是证明最终效果已经很好，而是证明系统已经能够从页面级检索进一步返回区域级证据节点。后续的研究重点就是通过强模型、重排序、多模态融合和更精细节点切分来提高 Region Hit。

## 五、研究边界与风险相关问题

### Q17：你的论文是不是把太多东西都放进来了？

**建议回答：**

我会控制研究边界。本文不从零训练多模态基础模型，不把 OCR、表格识别、图表数值抽取作为主创新点，而是把这些作为工具或扩展模块。论文主线始终围绕多粒度证据组织、页面-区域协同检索、证据增强生成和可信验证。

在实验上，我会优先保证中文年报和一个公开数据集上的完整对比实验、消融实验和错误分析；其他数据集和视觉图表处理作为补充验证，避免范围过大。

### Q18：如果后续视觉模型跑不动怎么办？

**建议回答：**

视觉检索会作为增强模块，而不是唯一主线。主干方法仍然是文本检索、版面信息和区域证据定位。如果视觉模型受算力限制，可以采用三种策略：

1. 先只做页面图像 embedding，不做复杂区域视觉推理；
2. 使用小规模样本或公开子集做视觉检索验证；
3. 保留文本和版面检索作为主实验，视觉检索作为补充消融。

这样即使视觉模块受限，也不会影响论文主线完成。

### Q19：如果 OCR 或 PDF 解析出错，会不会影响实验？

**建议回答：**

会影响，所以我会把解析错误作为实验误差来源单独记录。当前中文年报主要是原生 PDF，PyMuPDF 抽取效果相对稳定。对于扫描件或图片型 PDF，后续会接入 OCR，并记录 OCR 置信度。

实验分析中会区分解析错误、检索错误、重排序错误和生成错误，避免把底层解析问题误判为检索方法问题。

### Q20：你的可信验证会不会过度依赖大模型判断？

**建议回答：**

不会只依赖 LLM-as-judge。对于财务数值类问题，会优先使用规则校验，例如数值是否一致、单位是否一致、指标名称是否匹配、答案是否出现在证据节点中。对于文本型问题，再结合证据覆盖度、检索置信度和 LLM verifier 进行判断。

也就是说，可信验证会采用“规则校验 + 证据覆盖 + 模型判断 + 人工抽样复核”的组合方式，降低单纯依赖大模型判断带来的不稳定性。

## 六、现场简短总结回答

### 如果老师问：你这个论文到底研究什么？

**30 秒回答：**

我的论文研究的是多模态长文档中的证据检索与可信生成。简单说，不是让大模型直接读完整 PDF 回答，而是先把 PDF 解析成页面、段落、表格块、表格行、图表区域等证据节点，再通过页面级粗召回和区域级细定位找到证据，最后基于证据生成回答，并验证答案是否被证据支持。如果证据不足，系统会二次检索或拒答。

### 如果老师问：你现在已经做了什么？

**30 秒回答：**

目前我已经完成中文年报的第一阶段检索实验，处理了 20 份年报 PDF，得到 5327 个页面、99304 个细粒度证据节点，并人工修订了 160 条问答样本。实验实现了 BM25-page、Dense-page 和 Page→Region 三类 baseline，并完成 Page Recall、MRR、nDCG 和 Region Hit 等指标评价，初步验证了页面级召回和区域级定位结合的可行性。

**30 秒回答：**

老师，这个方向已有相关工作，本文是在已有研究基础上的进一步细化和组合创新。区别在于本文把长文档证据建模到页面、段落、表格行等多粒度节点，并采用页面级召回和区域级定位的两阶段检索，同时加入证据支持性验证和拒答机制。重点不是重复某一个模型，而是解决真实长文档 RAG 中证据定位粗、引用不可靠和答案难验证的问题。

### 如果老师问“你的输入输出是什么，怎么落地”，你可以这样回答：

**30 秒回答：**

本文系统的输入主要是 PDF 长文档和用户问题，例如年度报告、招股说明书、合同、政策文件等。系统先把 PDF 解析成页面和证据节点，再根据用户问题进行页面级召回和区域级证据定位，最后输出答案、来源文档、页码、证据片段、区域位置和支持性判断。它可以应用在金融年报分析、合同审阅、招股说明书风险审查、政策文件问答和企业知识库问答等场景。相比普通问答系统，它的优势是答案可追溯、证据可复核，证据不足时可以拒答。
